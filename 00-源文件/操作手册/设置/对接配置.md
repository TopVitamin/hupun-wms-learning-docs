# 对接配置

## 一、ERP/OMS对接
### **万里牛ERP对接步骤**
#### 第一步：ERP开启模块
在万里牛ERP联系在线客服，开启“万里牛直连对接”增值模块

![1702449975906-ce4e27d2-f9e6-48ae-8998-ddb7fb75d368.png](./img/t_vKT2VLdPWO5MSx/1702449975906-ce4e27d2-f9e6-48ae-8998-ddb7fb75d368-505656.png)

#### 第二步：WMS获取验证码
①. 货主管理页面新增货主，若是无货主直接忽略该操作直接进行②操作。

②. 对接配置页面用对接编码查询到该货主，点击未连接，点击获取验证码(验证码有效期15分钟要注意下)，复制验证码。

![1702449976375-f6abf96b-3a93-463c-b052-c6c0e217c2bb.png](./img/t_vKT2VLdPWO5MSx/1702449976375-f6abf96b-3a93-463c-b052-c6c0e217c2bb-874388.png)

#### 第三步：ERP里用验证码配置连接
在ERP系统中的云仓控制台界面，选择万里牛直连配置，点击新增配置，输入WMS系统中复制的验证码，选择要对接的仓库并输入WMS仓库编码，点击保存即可。

![1744609730403-63e18f26-0d3c-4bc2-b99d-f192f47d369f.png](./img/t_vKT2VLdPWO5MSx/1744609730403-63e18f26-0d3c-4bc2-b99d-f192f47d369f-928159.png)

#### 第四步：WMS系统中刷新页面，对接配置页面用对接编码查询到该货主，点击已连接，查看ERP的对接公司是否正确。
![1702449977844-f7f7a31f-0354-4d1b-abfb-e9e6fc7323bc.png](./img/t_vKT2VLdPWO5MSx/1702449977844-f7f7a31f-0354-4d1b-abfb-e9e6fc7323bc-509674.png)

#### 第五步：货主对接成功，接下来可以同步商品、建采购订单等操作了。
 

### **非万里牛ERP对接（奇门）**
请以奇门等标准对接模式对接，需要ERP方发起奇门对接申请后联系WMS客服/实施操作，简要流程。

+ ERP发起奇门对接，万里牛WMS奇门AppKey=23087164
+ WMS货主管理新增货主，复制货主编码
+ 联系WMS客服/实施，提供新增的货主编码+上游ERP名称或AppKey，完成对接配置等待生效



### ERP扩展业务
:::color3
超出奇门官方标准的场景用法配置，不同ERP有不一样的用法，需选定对应系统类型才可起效

:::

对接配置处对接系统新增聚水潭ERP、旺店通(企业版)ERP、其他ERP，支持对接相关扩展业务：

![1744596048545-dfa63df8-acf8-4411-8a72-b04a3533d588.png](./img/t_vKT2VLdPWO5MSx/1744596048545-dfa63df8-acf8-4411-8a72-b04a3533d588-515249.png)

![1785231393539-5c4387b8-4441-41a3-93cd-c5fad7aba84a.png](./img/t_vKT2VLdPWO5MSx/1785231393539-5c4387b8-4441-41a3-93cd-c5fad7aba84a-053762.png) 

其中：

1).若未开启扩展业务开关时，对应操作在提交或确认时系统会报错提示，如：原单入库开关未开启！

2).若开启扩展业务开关，则支持对应操作，并将数据回传给上游。

3).多次入库仅针对采购入库预约单，若开启多次入库，则允许对同一个预约单进行多次部分入库操作，直至入库数量=预约数量；若未开启，则第一次确认入库后，预约单变成“完成”，不允许继续入库。

4).选择奇门+其他模式时新增验货、疑难件入库回传，支持独立配置回传单据类型。

5).支持设置无对接+无系统配置，用于<font style="color:rgb(60, 67, 83);">有货主是线下业务，使用的ERP不具备对接能力或没有ERP，需要仅在WMS中进行出入库库存管理。</font>

<font style="color:rgb(60, 67, 83);">6).旺店通（企业版）ERP，支持原单入库</font>

<font style="color:rgb(60, 67, 83);">7).序列号异步回传</font>

![1776052125916-ba6e35f4-3dd5-455a-ae1a-2384d5ebcdc5.png](./img/t_vKT2VLdPWO5MSx/1776052125916-ba6e35f4-3dd5-455a-ae1a-2384d5ebcdc5-875642.png)

开启后可分别设置不同业务单据的序列号回传方式和回传接口

8).拆单发货回传：多次发货（每单一次）、尾单发货一次（全部发货完成时）

订单拆分成多个子单时，若配置多次发货，则每一个子单发货时通知上游（仅回传当前子单明细，部分发货标记），直到最后一个子单发货时通知上游（仅回传当前子单明细，全部发货标记）；若配置尾单发货一次，则仅在最后一个子单（即尾单）发货时通知上游（回传所有关联子单明细，全部发货标记），其他子单发货时不通知。

注：若订单为主子单子母件，则默认按尾单发货一次回传。

9).多包裹订单不回传子单号

未开启时：多包裹订单发货回传时会回传所有包裹结构；

开启+勾选多包裹：多包裹订单发货回传时，所有包裹明细合并，无包裹结构；

开启+勾选子母件：子母件订单发货回传时，所有包裹明细合并，无包裹结构。

###### 商品新增-特殊场景
**<u>配置1：商品编码重复时允许创建，自动增加前缀【预设值AA】</u>**

:::color3
**场景：多货主商品编码重复**

云仓多货主场景中，多个ERP编码规则太简单。比方说编码都是001，但实物跟条码都完全不相同。例如一个货主的001是Iphone，另一个货主的001是铅笔

:::

+ 未启用时，上游推送编码重复的商品，会在现有的商品上增加新推送货主授权；
+ 启用时，上游推送编码重复的商品允许添加，且会在商品编码前自动增加预设前缀，生成一条新的商品信息。



例：WMS系统已存在的商品信息：货主h01，商品编码bs0100，商品条码tm0100。上游推送商品信息：商品编码bs0100，商品条码tm0100-1，货主h02。

1. 货主h02未启用【配置1】时，推送成功，在现有商品bs0100（商品条码tm0100）上增加货主h02授权。
2. 货主h02启用【配置1】时，推送成功，新生成一条商品信息，商品编码AAbs0100，商品条码tm0100-1，货主h02，建立WMS商品编码AAbs0100与ERP商品编码bs0100之间的映射关系。

****

**异常场景-停启用配置：**

+ **停用后：**
    - **历史商品**：已生效的商品更新/订单推送依然生效，同例2效果；
    - **新商品**：新推送商品，配置不再生效，同例1效果；
+ **再启用：**仅对启用后新推送商品生效，同例2效果；

**异常场景-修改配置：**

以例2为展开，修改配置AA->BB：

+ **历史商品**：AAbs0100不受影响，可按原始bs0100更新商品信息/推送订单
+ **新商品**：推送编码bs0101，创建时为BBbs0101

**异常场景-修改商品信息：**

+ **例1未起效商品，修改商品编码**：修改编码为bs0101后，ERP推送bs0100订单时会报错商品不存在；
+ **例2已起效商品，修改商品编码**：修改编码为bs0101后，ERP推送bs0100订单时依然成功，识别为bs0101；如ERP修改编码等情况需要修改WMS编码想保持一致的，请删除商品重新推送；
+ **修改其他商品资料**：无特殊逻辑，均直接生效以及可被ERP更新。



**<u>配置2：商品条码重复时允许创建，自动增加后缀“++随机数”</u>**

:::color3
**场景：商品条码一样，需要细分规格**

有些商品含有多个规格，比方说红色/蓝色/黄色。库存管理时3个颜色需要独立管理，但3个颜色的商品的条码又是完全一致的。

:::

+ 未启用时，上游推送条码重复的商品，会报错提示；
+ 启用时，上游推送条码重复的商品允许添加，且会在商品条码后自动增加随机数，生成一条新的商品信息。后期可在wms系统中把随机数改成商品特征值，比方说++红，++蓝。



例：WMS系统已存在的商品信息：货主h01，商品编码bs0100，商品条码tm0100。上游推送商品信息：商品编码bs0100-1，商品条码tm0100，货主h02。

1. 货主h02未启用【配置2】时，推送失败，提示条码重复。
2. 货主h02启用【配置2】时，推送成功，新生成一条商品信息，商品编码bs0100-1，商品条码tm0100++随机数，货主h02。



**异常场景-停启用配置：**

+ **停用后：**
    - **历史商品**：已生效的商品更新/订单推送依然生效，同例2效果；
    - **新商品**：新推送商品，配置不再生效，同例1效果；
+ **再启用：**仅对启用后新推送商品生效，同例2效果；

**异常场景-修改商品信息：**

+ **例1未起效商品，修改商品编码：**修改编码为bs0101后，ERP推送bs0100订单时会报错商品不存在；
+ **例2已起效商品，修改商品编码：**修改编码为bs0100++1后，ERP推送bs0100订单时会报错商品不存在；
+ **修改其他商品资料：**无特殊逻辑，均直接生效以及可被ERP更新。



**<u>配置3：商品条码重复时允许创建，映射至同一商品（分销场景）</u>**

:::color3
**场景：****<font style="color:rgb(60, 67, 83);">多货主不相同编码，实际为一样的货（条码一样）</font>**

云仓多货主场景中，部分货主是上下游分销等供销关系，云仓经常会发一些相同的商品（实物相同且条码相同）。

如果仓库中有10个这样的货主，那么同一个实物商品要维护10套商品信息，为了减少管理跟操作成本，需要WMS当作同一个商品管理

:::

+ 未启用时，上游推送条码重复的商品，会报错提示；
+ 启用时，上游推送条码重复的商品允许添加，且会在现有商品信息上增加货主授权。



例：WMS系统已存在的商品信息：货主h01，商品编码bs0100，商品条码tm0100。上游推送商品信息：商品编码bs0100-1，商品条码tm0100，货主h02。

1. 货主h02未启用【配置3】时，推送失败，提示条码重复。
2. 货主h02启用【配置3】时，推送成功，在现有商品bs0100（商品条码tm0100）上增加货主h02授权，建立WMS商品编码bs0100与ERP商品编码bs0100之间的映射关系，之后该货主推送bs0100-1即认为是bs0100同一个商品。



**异常场景-停启用配置：**

+ **停用后：**
    - **历史商品**：已生效的商品更新/订单推送依然生效，同例2效果；
    - **新商品**：新推送商品，配置不再生效，同例1效果；
+ **再启用：**仅对启用后新推送商品生效，同例2效果；

**异常场景-修改商品信息：**

+ **正常商品修改商品编码**：修改编码为bs0101后，ERP推送bs0100订单时会报错商品不存在；
+ **起效商品修改商品编码**：修改编码为bs0101后，ERP推送bs0100订单时依然成功，识别为bs0101；如ERP修改编码等情况需要修改WMS编码想保持一致的，请删除商品重新推送；
+ **修改其他商品资料**：无特殊逻辑，均直接生效以及可被ERP更新。



**<u>配置4：不新增重量/长宽高体积</u>**

:::color3
场景：上游的商品物理信息，往往是采购供应商预估值，误差较大，大部分需要仓库到货后实际测量过才准确。

本功能经常配合入库商品校验使用。

:::

+ 未启用时，上游推送新商品信息，所有字段按照推送数据正常接收；
+ 启用时，上游推送新商品信息，重量、长宽高体积字段不按推送数据显示，显示0。



**多配置生效优先级：**

+ 配置2和配置3不支持同时启用；
+ 配置1和配置3同时启用时，配置3的优先级更高，优先配置3的逻辑；
+ 配置1和配置2同时启用时，都生效。

###### 商品更新
未启用商品更新时，无法从上游推送更新商品信息到WMS系统；启用后则允许从上游推送更新商品到WMS系统。



启用后显示如下配置：

配置1：不更新时处理：接口成功但不更新数据、接口报错

接口成功但不更新数据：上游推送更新商品信息时，包含部分字段勾选了不更新处理，则允许接收更新信息，但不会对勾选了不更新的字段进行覆盖。

接口报错：上游推送更新商品信息时，包含部分字段勾选了不更新处理，则接口直接报错。



配置2：不更新商品名称/条码/重量/长宽高体积/商品分类/货号/简称/品牌/存储条件

未启用时，上游推送新商品信息，所有字段按照推送数据正常接收；未启用时，上游推送新商品信息，勾选了不更新的字段不变，其他字段做更新处理。



**注：启用商品新增下的配置1、2、3启用状态对于商品更新功能无影响。**

#### 库存处理
![1775806284822-591cc572-3027-408a-b6c4-0176a2f92bb6.png](./img/t_vKT2VLdPWO5MSx/1775806284822-591cc572-3027-408a-b6c4-0176a2f92bb6-225428.png)

使用场景：<font style="color:rgb(60, 67, 83);">库存差异进行调整的时候货主不允许回传盘点单，会影响财务结算，需要传其他出入库单。</font>

##### 库存调整使用库存异动通知接口	
开启开关后，库存调整回传外部会调用库存异动通知接口，并且可以自定义选择或者填写需要回传上游的盘盈/盘亏类型；

case：勾选库存调整使用库存异动通知接口开关，盘盈类型下拉选择【THYRK】，盘亏类型自定义填写【PYCK】

库存调整单：商品A，调整差异数：10；商品B，调整差异数：-5；

回传外部，使用库存异动通知接口

消息1：业务类型：THYRK；商品：商品A；数量：10

消息2：业务类型：PYCK；商品：商品B；数量：5

##### 正次转换使用库存异动通知接口	
开启开关后，正次转换回传外部会调用库存异动通知接口，并且可以自定义选择或者填写需要回传上游的正品入库单/出库单类型和次品入库单/出库单类型；

①<font style="color:rgb(0, 0, 0);">拆分2张单据(如出入库)</font>

![1781143348187-0e1c3add-322b-4081-8736-b62603756ea6.png](./img/t_vKT2VLdPWO5MSx/1781143348187-0e1c3add-322b-4081-8736-b62603756ea6-406356.png)

case：勾选正次转换使用库存异动通知接口开关，正品入库单类型下拉选择【THYRK】，正品出库单类型自定义填写【ZPCK】；次品入库单类型下拉选择【LYRK】，次品出库单类型自定义填写【PTCK】

**场景1：次品库存管理-标准模式**

**（正常回传正次品类型）**

正品转次：商品A：数量5

次品转正：商品B：数量3

回传外部，使用库存异动通知接口

消息1：业务类型：ZPCK；商品：商品A；数量：5；商品类型：正品

消息2：业务类型：LYRK；商品：商品A；数量：5；商品类型：次品

消息3：业务类型：PTCK；商品：商品A；数量：3；商品类型：次品

消息4：业务类型：THYRK；商品：商品A；数量：3；商品类型：正品

**场景2：次品库存管理-对内模式**

**（均按照正品类型回传）**

正品转次：商品A：数量5

## 三、溯源系统对接
按对接系统/平台类型添加配置，对指定仓库、指定货主及指定单据类型生效。

![1767694798342-ab0cb8c3-efe6-4d1b-8abd-de96f4d68ed4.png](./img/t_vKT2VLdPWO5MSx/1767694798342-ab0cb8c3-efe6-4d1b-8abd-de96f4d68ed4-798425.png)

业务校验模式：

+ 不校验：业务单据有关联溯源上传记录未完成时，可以直接完结业务单据，无校验；
+ 强校验：业务单据有关联溯源上传记录未完成时，不允许直接完结业务单据，需等溯源上传记录完成后才能完结；
+ 弱校验：业务单据有关联溯源上传记录未完成时，有一个弱提醒，二次确认后允许完结业务单据。

#### 对接系统平台：阿里健康-码上放心
出库模块根据勾选配置，在出库时根据配置中相应店铺使用对应的接口进行溯源码（系统内的序列号）的上传

![1777371371899-b6084165-f3a6-4e45-86ef-1d013ba149d2.png](./img/t_vKT2VLdPWO5MSx/1777371371899-b6084165-f3a6-4e45-86ef-1d013ba149d2-978906.png)

提示：

①本页面要开通对应增值模块【UDI追溯回传】后才显示；

②不同配置间仓库+货主+单据类型不允许重复；

③有未完成的溯源上传记录时，不允许修改或删除对应配置（除对接名称、备注）。
