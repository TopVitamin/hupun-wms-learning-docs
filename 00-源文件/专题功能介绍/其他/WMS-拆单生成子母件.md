# WMS-拆单生成子母件

### 多件订单自动拆单并跨订单取子母件面单
#### 一、概述
“拆单+跨订单取子母件”是一套从多件订单拆解到拆后包裹取子母件面单的全链路解决方案。核心解决两个问题：一是多件订单因商品分散在不同库区导致单人拣货效率低、无法与单件订单组波次的问题；二是拆单后多个包裹无法享受子母件计费优惠、每单独立派送成本高的问题。

该方案包含两个阶段：**拆单阶段**——在订单审核环节按商品明细将多件订单拆成多个平级子单，每个子单只含少量商品，可与单件订单一起组波次；**取号阶段**——对已拆分的多个主子单一次性获取子母件电子面单，多个包裹共享一个母单号，快递统一按子母件计费。

#### 二、使用场景
**场景一：多件订单拣货效率低**

家居家私类等大件的客户，一张订单往往包含多件不同商品（如衣柜+床头柜+书桌）。传统做法是整单一起拣货，但仓库库区大，拣货员推车从头走到尾，动线长、耗时长。更麻烦的是，多件订单无法与单件订单组到同一个波次，导致波次数量少、拣货员跑一趟只能拣几单。部分仓库尝试让多个拣货员用PDA接力拣货，但交接环节经常出错，漏拣、重复拣时有发生。

**场景二：拆单后无法享受子母件运费优惠**

拆单后多个主子单对应多个包裹，客户希望使用子母件电子面单（一个母单号+多个子单号），快递侧按子母件计费，平均每单可节省运费。但此前主子单拆出后仍按普通订单独立取号，无法享受子母件优惠，每单都要付一笔首重费用，成本偏高。

**适用行业**：家居家私（衣柜、床头柜、书桌椅等）、大件商品、多件组合销售类电商。

#### 三、怎么设置
##### 3.1 业务配置
进入【业务配置】→【拆单策略】，策略列表直接在页面外层展示，含策略名称、平台/店铺、承运商、策略详情、优先级、自动拆单、自动提交等字段。新增策略最多20条。

##### 3.2 拆单策略配置
**基本信息**：

+ **策略名称**：10字符以内，必填且唯一
+ **优先级**：正整数，可重复，按数值从小到大匹配

#### 四、作业流程
### 4.1 拆单执行
订单进入订单审核后，按优先级匹配拆单策略：

**不支持的订单类型**：

+ 得物直发订单
+ 预售订单
+ 外贸订单
+ 已有多包裹的订单

### 4.2 跨订单取子母件
主子单拆分完成后，在订单审核或订单查询中勾选需要关联的主子单订单，点击【获取子母件】。

**取号入口**：

+ **自动入口**：仅针对拆单主子单生效，策略中配置针对主子单自动获取子母件
+ **手动入口**：以实际界面勾选结果为准

### 4.3 改快递/取消
+ 界面勾选范围内的订单可整体改快递或取消
+ 主子单关联子母件单号且未打印快递单时 → 全部同步变更
+ 已有打印记录的关联子母件 → 禁止修改，会有提示“有关联子母件已打印快递单，不允许修改，请使用拆单召回”

### 4.4 外部发货回传
对接配置中新增“拆单发货回传”选项：

![1785998836170-4646476a-b179-4801-a61d-d7f3f41e5b71.png](./img/tUrKbC9gzBP4kYKt/1785998836170-4646476a-b179-4801-a61d-d7f3f41e5b71-098081.png)

+ **多次发货（每单一次，默认）** ：每个子单发货即回传，confirmType按标准值
+ **尾单发货一次（全部完成时）** ：非尾单发货只完成节点不回传，尾单发货时回传所有主子单单号及原订单明细，包裹顺序为主单→各子单

### 4.5 订单召回
订单审核列表操作区新增“拆单召回”按钮：

+ 输入主单号即可召回所有关联主子单
+ 主子单外部状态变更为【拦截】
+ 召回后原主单系统单号后缀为T1C1，重新创建WD主单号（保证给ERP回传的主单号不变）

## 五、业务效果
1. **拣货效率提升**：多件订单在通过接单拆单后，可变成单件订单一起高效组波次，拣货员不需要跑遍全仓，拣货效率明显提升。
2. **运费成本降低**：拆出的多个主子单可用子母件面单统一取号，平均每单节省运费，同时避免多张单子分别派送带来的多次派件问题。
3. **数据基础统一**：主子单标记为后续3PL账单归集、多包裹通知、子母件取号等能力提供统一的数据基础。
