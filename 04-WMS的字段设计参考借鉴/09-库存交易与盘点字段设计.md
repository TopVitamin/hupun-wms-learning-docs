# 09 库存交易与盘点字段设计

> 参考范围：`01-按章节拆分的md文件/07-仓内作业.md`、`01-按章节拆分的md文件/08-库存管理.md`、`01-按章节拆分的md文件/03-仓内策略.md`、`03-WMS产品设计精华知识借鉴/09-库存交易与盘点设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

库存移动、调拨、主动/被动补货、冻结、解冻、盘点任务、动态盲盘、库存差异、库存调整、正次品转换和货权转移。

### 1.2 包含哪些功能

交易单创建、来源和目标位置确认、任务执行、盘点采集、差异确认、冻结/解冻、调整生效、货权转移和库存流水记录。

### 1.3 业务场景与要解决的问题

本章解决库存已经存在后如何移动、隔离、清点、调整和转移货权。操作手册明确库存移动支持 PC/PDA，库区预警可自动创建补货单，盘点任务有待作业、作业中、已完成、已关闭，库存差异量用于校准库存，货权转移属于 3PL 场景。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 库存交易单 | 表达移库、调拨、补货等内部库存动作 | 头 1:N 明细 | P0 |
| 库存交易明细 | 保存来源/目标位置和数量 | 交易单 1:N 明细 | P0 |
| 冻结记录 | 保存冻结和释放的对象、数量、原因 | 库存余额 1:N 记录 | P0 |
| 盘点单/任务 | 表达盘点范围和现场作业 | 盘点单 1:N 明细/任务 | P0 |
| 库存调整单 | 处理账面与实物差异 | 差异 1:N 调整 | P0 |
| 货权转移记录 | 保存货主间库存归属变化 | 3PL 条件能力 | 后置/条件采用 |

## 3. 字段设计原则

- 内部位置移动改变库位维度，不应无依据改变仓库总量。
- 冻结/解冻、盘点和调整不能直接覆盖库存余额，必须记录原因、操作人和生效时间。
- 盘点数量是现场事实，系统数量是盘点时的比较基线，二者要同时保留。
- 盘点差异与库存调整不是同一对象：前者发现问题，后者改变账面数量。
- 货权转移必须保留转移前后货主和审批/操作证据，不能用修改 `owner_id` 代替历史交易。

## 4. 字段定义与设计说明

### 4.1 库存交易 `inventory_movement`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `movement_id` | 交易单标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `movement_no` | 交易单号 | 业务编号 | VARCHAR | 必填 |
| `movement_type` | 交易类型 | 移库/调拨/补货/属性转换等 | ENUM | 必填 |
| `warehouse_id` | 仓库 | 关联 ID | BIGINT/UUID | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 多货主必填 |
| `source_doc_no` | 来源单号 | 预警、订单或调拨单号 | VARCHAR | 有来源时必填 |
| `status` | 交易状态 | 草稿/待作业/作业中/完成/取消 | ENUM | 默认草稿 |
| `created_by` | 创建人 | 用户 ID | BIGINT/UUID | 系统生成 |
| `effective_at` | 生效时间 | 日期时间 | DATETIME | 完成时写入 |
| `reason_code` | 原因编码 | 调整/转换原因 | VARCHAR/ENUM | 异常场景必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `movement_type` | 创建交易时选择或系统生成 | 不同类型的来源、方向和审批规则不同 | 支持更多仓内交易 | 让库存流水可以解释 | 参考事实＋建议设计 |
| `source_doc_no` | 预警、订单或人工操作触发时写入 | 自动补货必须能回到触发预警，人工调整必须有原因 | 支持异常闭环和自动化重试 | 防止无来源的库存变化 | 参考事实＋建议设计 |
| `status` / `effective_at` | 任务执行和确认时更新 | 创建交易不等于库存已变更，只有生效才写入流水 | 支持取消、重试和审计 | 避免重复扣减或增加库存 | 建议设计 |
| `reason_code` | 差异、冻结、转换时写入 | 原因必须可分类统计，备注只能作为补充 | 支持盘点分析和责任追溯 | 解释为什么发生异常变化 | 建议设计 |

### 4.2 交易明细、冻结与解冻 `movement_line` / `freeze_record`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `movement_line_id` | 交易明细标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `source_location_id` | 来源库位 | 关联 ID | BIGINT/UUID | 需要来源时必填 |
| `target_location_id` | 目标库位 | 关联 ID | BIGINT/UUID | 需要目标时必填 |
| `inventory_attr` | 库存属性 | 正品/次品等 | ENUM | 默认正品，待确认 |
| `lot_no` | 批次 | 批次号 | VARCHAR | 按规则必填 |
| `serial_no` | 序列号 | 唯一序列号 | VARCHAR | 按规则必填 |
| `planned_qty` | 计划数量 | 数量 | DECIMAL | 必填 |
| `confirmed_qty` | 确认数量 | 数量 | DECIMAL | 默认 0 |
| `freeze_id` | 冻结记录标识 | 统一 ID | BIGINT/UUID | 冻结场景生成 |
| `freeze_qty` | 冻结数量 | 数量 | DECIMAL | 必填 |
| `freeze_reason` | 冻结原因 | 原因编码/文本 | VARCHAR/ENUM | 必填 |
| `released_qty` | 已解冻数量 | 数量 | DECIMAL | 默认 0 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `source_location_id` / `target_location_id` | 交易创建和现场确认时写入 | 来源、目标库位必须符合用途、容量、混放和库存属性约束 | 支持路径分析和库位利用率 | 防止货物账面移动到错误位置 | 参考事实＋建议设计 |
| `planned_qty` / `confirmed_qty` | 任务生成和执行时更新 | 支持部分完成，剩余数量不能丢失 | 支持移库、补货和盘点进度 | 解释作业中断和未完成交易 | 建议设计 |
| `freeze_qty` / `released_qty` | 冻结和解冻动作更新 | 解冻不能超过冻结未释放数量，必须关联原冻结记录 | 支持质量隔离和异常暂存 | 防止冻结量长期悬挂 | 建议设计 |
| `inventory_attr` / `lot_no` / `serial_no` | 交易匹配库存时带入 | 不同库存身份不能被合并成无属性的数量 | 支持批次、序列号和正次品转换 | 保证转移后的库存身份准确 | 参考事实＋建议设计 |

### 4.3 盘点与库存调整 `cycle_count` / `stock_adjustment`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `count_id` | 盘点单标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `count_no` | 盘点单号 | 业务编号 | VARCHAR | 必填 |
| `count_scope` | 盘点范围 | 仓库/区域/库区/库位/SKU | ENUM/JSON | 必填 |
| `count_strategy_id` | 盘点策略 | 关联 ID | BIGINT/UUID | 策略盘点时可选 |
| `count_status` | 盘点状态 | 待作业/作业中/完成/关闭 | ENUM | 默认待作业 |
| `system_qty` | 盘点基准数量 | 数量 | DECIMAL | 盘点开始时固化 |
| `counted_qty` | 实盘数量 | 数量 | DECIMAL | 现场录入 |
| `difference_qty` | 差异数量 | 数量，可正可负 | DECIMAL | 系统计算 |
| `adjustment_id` | 调整单标识 | 关联 ID | BIGINT/UUID | 有差异调整时写入 |
| `adjustment_reason` | 调整原因 | 原因编码/文本 | VARCHAR/ENUM | 调整时必填 |
| `approved_by` | 审批人 | 用户 ID | BIGINT/UUID | 需要审批时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `count_scope` / `system_qty` | 创建盘点任务和开始盘点时写入 | 盘点范围和基准数量必须固化，否则现场作业期间数据漂移无法解释 | 支持动态盲盘和冻结盘点 | 形成可复核的盘点基线 | 参考事实＋建议设计 |
| `counted_qty` / `difference_qty` | 现场盘点和系统比较时写入 | 盘点实数不应直接覆盖系统数，差异必须保留 | 支持差异率和盘点准确率 | 识别账实不符 | 参考事实＋建议设计 |
| `adjustment_id` / `adjustment_reason` | 调整生效时关联 | 盘点发现问题与账面调整分开，且调整要能通知外部系统 | 支持 ERP 对账和审计 | 让差异处理可追踪 | 参考事实＋建议设计 |
| `approved_by` | 审批通过时写入 | 是否需要审批由业务配置和权限决定 | 支持高价值商品盘点控制 | 降低直接调整风险 | 参考事实＋待确认 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 移库、补货和库存属性变更 | 来源/目标库位、数量、属性 | 闭合仓内库存移动 |
| P0 | 盘点与差异识别 | 基准量、实盘量、差异量 | 保留盘点事实，不直接改余额 |
| P0 | 冻结与解冻 | 冻结量、原因、释放量 | 支撑质量和异常隔离 |
| P0 | 库存调整和流水 | 原因、前后数量、来源 | 形成可审计的库存纠错链 |
| P1 | 动态盲盘、货权转移 | 范围、货主、策略 | 3PL 或复杂仓库按需启用 |
| 后续 | 自动盘点、机器人移库和智能差异判断 | 设备、算法字段 | 条件能力，不进入核心余额模型 |

## 6. 跨模块依赖、拓展与待确认

- 读取库存余额、库位、商品属性、策略和任务；交易生效后写入库存流水，并可能通知 ERP/OMS。
- 可拓展到 3PL 货权转移、批次级盘点、质量冻结、自动补货和库位迁移。
- 盘点期间是否冻结库存、调整是否必须审批、货权转移是否产生实物库存流水、逆向冲销规则，均待确认。
