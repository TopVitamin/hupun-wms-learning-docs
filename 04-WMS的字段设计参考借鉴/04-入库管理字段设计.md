# 04 入库管理字段设计

> 参考范围：`01-按章节拆分的md文件/04-入库操作.md`、`01-按章节拆分的md文件/03-仓内策略.md`、`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`03-WMS产品设计精华知识借鉴/04-入库管理设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

入库预约、采购入库、调拨入库、其他入库、销退入库、入库单、入库明细和来源单据关联。

收货、清点、质检和上架现场执行在本目录的 05 章展开；本章负责表达“为什么要入库、计划入库什么、入库进度如何”。

### 1.2 包含哪些功能

入库请求接收、预约创建、来源单匹配、入库类型区分、计划数量维护、分批收货、部分入库、原单入库、快速入库、取消和关闭。

### 1.3 业务场景与要解决的问题

入库管理解决采购、调拨、退货或其他到货在进入仓库前缺少计划的问题。字段必须支持计划量与实收量分开、短收/溢收可解释、同一来源单不重复入库，并能把预约、现场记录、入库生效和库存流水串起来。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 入库预约/通知单 | 表达预计到货和入库意图 | 头 1:N 明细 | P0 |
| 入库预约明细 | 表达 SKU 级计划数量和来源行 | 被收货、入库任务引用 | P0 |
| 收货记录 | 表达每次现场实际收货 | 预约 1:N 收货记录 | P0 |
| 入库单 | 表达已确认的入库结果 | 可由预约和收货产生 | P0 |
| 序列号/批次记录 | 表达实际收到的库存身份 | 入库明细 1:N 属性记录 | 按商品规则采用 |

## 3. 字段设计原则

- 入库预约、收货记录和入库生效单据必须区分，不能用一个状态字段覆盖三个阶段。
- 计划数量、实收数量、差异数量和生效数量必须分开，部分收货不能覆盖原计划。
- 采购、调拨、其他、销退等来源类型要能追溯到原始单据，但不能默认所有来源采用同一取消规则。
- 预约或入库单创建不等于库存增加；库存生效节点必须单独说明。
- 批次、效期、序列号和库存属性只在商品规则要求时采集，不能凭空给所有商品增加追溯字段。

## 4. 字段定义与设计说明

### 4.1 入库预约头 `inbound_notice`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `inbound_notice_id` | 入库预约标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `inbound_notice_no` | 入库预约单号 | 业务单号 | VARCHAR | 必填，系统生成或外部带入 |
| `external_no` | 外部单号 | 外部系统单号 | VARCHAR | 对接场景必填 |
| `inbound_type` | 入库类型 | 采购/调拨/其他/销退等 | ENUM | 必填 |
| `warehouse_id` | 入库仓库 | 关联 ID | BIGINT/UUID | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 多货主必填 |
| `supplier_id` | 供应商 | 关联 ID | BIGINT/UUID | 采购场景必填 |
| `expected_arrival_at` | 预计到货时间 | 日期时间 | DATETIME | 可选 |
| `status` | 预约状态 | 在途/部分收货/完成/关闭等 | ENUM | 默认待处理或在途 |
| `planned_qty` | 计划总数量 | 数量＋单位 | DECIMAL | 系统汇总 |
| `received_qty` | 已收总数量 | 数量＋单位 | DECIMAL | 默认 0 |
| `diff_qty` | 差异总数量 | 数量＋单位 | DECIMAL | 默认 0 |
| `source_doc_no` | 来源单号 | 采购/调拨/退货单号 | VARCHAR | 有来源时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `inbound_notice_no` | ERP 推送、手工创建或同步生成 | 需要区分内部业务单号和外部单号，支持查询和幂等 | 支持分批到货和多来源单关联 | 防止一批到货没有可追踪对象 | 参考事实＋建议设计 |
| `external_no` | 外部系统推送 | 同一外部单号的重复请求不能重复创建预约 | 支持接口补偿和重试 | 防止重复入库 | 建议设计 |
| `inbound_type` | 创建或同步时确定 | 入库类型影响来源校验、收货和回写 | 可扩展换货、样品、赠品等类型 | 让不同到货来源走正确规则 | 参考事实＋建议设计 |
| `planned_qty` / `received_qty` / `diff_qty` | 计划创建、现场收货和差异确认时更新 | 三者不能互相覆盖；差异要能定位到明细和原因 | 支持供应商到货准确率分析 | 解释部分收货、短收和溢收 | 参考事实＋建议设计 |
| `status` | 预约、收货和关闭动作触发 | 状态必须能判断是否允许继续收货或取消 | 支持待处理队列和超期预警 | 避免已关闭预约继续被正常处理 | 参考事实＋待确认 |

### 4.2 入库预约明细 `inbound_notice_line`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `inbound_line_id` | 入库明细标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `inbound_notice_id` | 入库预约 | 关联 ID | BIGINT/UUID | 必填 |
| `line_no` | 明细行号 | 正整数 | INT | 系统生成 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `source_line_no` | 来源明细行号 | 外部行号 | VARCHAR | 有来源时必填 |
| `planned_qty` | 计划数量 | 数量＋单位 | DECIMAL | 必填 |
| `received_qty` | 已收数量 | 数量＋单位 | DECIMAL | 默认 0 |
| `unit_code` | 收货单位 | 单位编码 | VARCHAR | 必填 |
| `lot_no` | 生产批次 | 批次号 | VARCHAR | 批次商品必填 |
| `production_date` | 生产日期 | 日期 | DATE | 效期商品按规则必填 |
| `expiry_date` | 过期日期 | 日期 | DATE | 效期商品按规则必填 |
| `inventory_attr` | 库存属性 | 正品/次品等 | ENUM | 默认正品，待确认 |
| `diff_reason` | 差异原因 | 原因编码/文本 | VARCHAR/ENUM | 有差异时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `source_line_no` | 接收外部单据时保存 | 必须与来源单号一起使用，不能只保留行号 | 支持来源行级回写和对账 | 防止多行同 SKU 无法核对 | 建议设计 |
| `planned_qty` / `received_qty` | 预约和现场作业更新 | 数量单位要明确，单位换算要回到基本单位 | 支持按箱、件、散件收货 | 解决箱规和收货数量不一致 | 参考事实＋建议设计 |
| `lot_no` / `production_date` / `expiry_date` | 收货或质检时采集 | 批次唯一粒度、效期校验和修改权限必须明确 | 支持先进先出、库龄和召回 | 解决批次级库存追溯 | 参考事实＋建议设计 |
| `inventory_attr` | 收货判定或异常处理时写入 | 次品不能只靠备注表达，否则库存和库位无法隔离 | 支持质检不合格、残次品和返修 | 防止正次品混用 | 参考事实＋建议设计 |
| `diff_reason` | 差异收货提交时写入 | 差异数量与原因必须同一层级，允许后续处理决定 | 支持供应商绩效和异常闭环 | 解释短收、溢收、拒收 | 归纳判断＋建议设计 |

### 4.3 收货记录与入库生效 `receiving_record` / `inbound_document`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `receiving_record_no` | 收货记录号 | 业务单号 | VARCHAR | 系统生成 |
| `inbound_notice_id` | 来源预约 | 关联 ID | BIGINT/UUID | 无预约快速入库时可空，待确认 |
| `received_at` | 收货时间 | 日期时间 | DATETIME | 操作时生成 |
| `receiver_id` | 收货人 | 用户 ID | BIGINT/UUID | 必填 |
| `received_qty` | 本次实收量 | 数量 | DECIMAL | 必填 |
| `accepted_qty` | 接收合格量 | 数量 | DECIMAL | 质检场景使用 |
| `rejected_qty` | 拒收/不合格量 | 数量 | DECIMAL | 有异常时记录 |
| `inbound_document_no` | 生效入库单号 | 业务单号 | VARCHAR | 生效后生成 |
| `effective_at` | 库存生效时间 | 日期时间 | DATETIME | 生效时生成 |
| `effective_flag` | 是否已生效 | `Y/N` | BOOLEAN | 默认 `N` |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `received_qty` | PDA/PC 收货确认 | 收货记录是现场事实，不能直接覆盖预约计划 | 支持按人、时间和批次分析收货效率 | 保留每次分批收货证据 | 参考事实＋建议设计 |
| `accepted_qty` / `rejected_qty` | 清点或质检后写入 | 质检不合格后续去向不能默认推导 | 支持隔离、退供应商或转次品 | 防止合格和不合格数量混入库存 | 建议设计＋待确认 |
| `effective_flag` / `effective_at` | 入库确认时写入 | 只有明确生效后才产生库存增加 | 支持重试、审计和库存流水追溯 | 避免重复确认造成重复入库 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 入库预约和入库单 | 单号、来源、仓库、货主、类型、状态 | 覆盖采购、调拨、其他和销退主链 |
| P0 | 计划/实收/差异数量 | 明细数量、差异原因 | 必须支持部分收货和异常解释 |
| P0 | 来源单关联和幂等 | 外部单号、来源单号、来源行号 | 防止重复预约和重复入库 |
| P1 | 扫码、快速入库、原单入库 | 条码、单位、来源明细 | 提高现场效率，具体入口按手册继续核对 |
| P1 | 分批收货和质检衔接 | 收货记录、合格/不合格量 | 与 05 章共同形成现场闭环 |
| 后续 | 疑难件智能匹配、平台专属入库 | 扩展来源、匹配结果 | 资料和业务确认后再扩展 |

## 6. 跨模块依赖、拓展与待确认

- 读取主数据的商品、条码、单位、批次和序列号规则；调用库位和上架策略；生效后写入库存余额和库存流水。
- 可拓展到预约时段、供应商到货绩效、收货质检隔离、退货疑难件和 ASN 协同。
- 收货即增加库存还是入库确认后增加、关闭预约后的继续收货、超收是否允许、质检不合格的去向，均待确认。
