# 05 收货、质检与上架作业字段设计

> 参考范围：`01-按章节拆分的md文件/04-入库操作.md`、`01-按章节拆分的md文件/01-基础信息与系统设置.md`、`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`01-按章节拆分的md文件/07-仓内作业.md`、`03-WMS产品设计精华知识借鉴/05-收货质检与上架作业设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

收货、清点、理货、质检、分批入库、容器装箱、上架指导和上架确认。

### 1.2 包含哪些功能

PC/PDA 收货、预约或无预约清点、商品/条码扫描、批次效期采集、质检判定、差异记录、目标库位推荐和上架确认。

### 1.3 业务场景与要解决的问题

操作手册明确 PC 和 PDA 都支持入库作业；清点可有预约或无预约；分批入库任务可以串联清点、质检等环节；入库也可以使用容器。字段要把“收到多少、质量如何、放到哪里、谁操作的”分开记录。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 收货任务 | 组织现场收货工作 | 来源预约 1:N 任务 | P0 |
| 清点记录 | 保存扫描或人工清点结果 | 任务 1:N 记录 | P0 |
| 质检记录 | 保存质量判定和原因 | 清点/收货 1:N 质检 | 按场景采用 |
| 上架任务 | 组织目标库位和上架动作 | 收货结果 1:N 任务 | P0 |
| 上架明细 | 保存 SKU、数量、批次和目标位置 | 任务 1:N 明细 | P0 |
| 容器作业记录 | 保存容器绑定和箱内明细 | 与收货/上架关联 | P1 |

## 3. 字段设计原则

- 现场实收是事实，预约计划是意图，二者不能互相覆盖。
- 质检结果、合格数量、不合格数量和后续处理决定分开保存。
- 目标库位必须保存实际确认结果，不能只保存系统推荐位置。
- 批次、效期、序列号和库存属性按商品管理规则采集；不适用时保持空值，不填虚构值。
- 收货、清点、质检和上架任务各自保留操作人、时间和状态，避免一张“入库单”承担现场全过程。

## 4. 字段定义与设计说明

### 4.1 收货与清点 `receiving_task` / `count_record`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `receiving_task_id` | 收货任务标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `source_notice_id` | 来源预约 | 关联 ID | BIGINT/UUID | 有预约时必填 |
| `task_no` | 收货任务号 | 业务编号 | VARCHAR | 必填 |
| `task_mode` | 作业模式 | 有预约/无预约/扫码等 | ENUM | 必填 |
| `operator_id` | 收货人 | 用户 ID | BIGINT/UUID | 提交时必填 |
| `started_at` | 开始时间 | 日期时间 | DATETIME | 领取时写入 |
| `completed_at` | 完成时间 | 日期时间 | DATETIME | 完成时写入 |
| `status` | 任务状态 | 待作业/作业中/完成/取消 | ENUM | 默认待作业 |
| `count_record_no` | 清点记录号 | 业务编号 | VARCHAR | 清点保存时生成 |
| `counted_qty` | 本次清点数量 | 数量 | DECIMAL | 必填 |
| `difference_qty` | 清点差异数量 | 数量，可正可负 | DECIMAL | 默认 0 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `task_mode` | 收货入口确定 | 有预约和无预约的来源校验不同，不能共用同一必填规则 | 支持疑难件和自由收货 | 防止没有来源的货物直接入账 | 参考事实＋建议设计 |
| `operator_id` / `started_at` / `completed_at` | 领取、提交时写入 | 现场责任和作业时长要可追溯 | 支持收货绩效和异常追责 | 解释数量差异由谁产生 | 建议设计 |
| `counted_qty` / `difference_qty` | 扫描或清点提交时计算 | 不能用清点结果覆盖预约计划；差异要回到明细 | 支持供应商到货准确率 | 解释短收、溢收和漏收 | 参考事实＋建议设计 |

### 4.2 质检 `quality_check`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `qc_id` | 质检记录标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `source_count_id` | 来源清点记录 | 关联 ID | BIGINT/UUID | 有清点时必填 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `checked_qty` | 检验数量 | 数量 | DECIMAL | 必填 |
| `accepted_qty` | 合格数量 | 数量 | DECIMAL | 默认 0 |
| `rejected_qty` | 不合格数量 | 数量 | DECIMAL | 默认 0 |
| `qc_result` | 质检结果 | 合格/部分合格/不合格 | ENUM | 必填 |
| `reject_reason` | 不合格原因 | 原因编码/文本 | VARCHAR/ENUM | 不合格时必填 |
| `disposition` | 后续处理 | 隔离/退回/转次品/待处理 | ENUM | 不合格时待确认 |
| `checked_by` | 质检人 | 用户 ID | BIGINT/UUID | 提交时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `checked_qty` / `accepted_qty` / `rejected_qty` | 质检提交时写入 | 三者数量关系必须满足 `checked_qty = accepted_qty + rejected_qty`，特殊复检规则待确认 | 支持质量统计和供应商考核 | 防止不合格数量进入正常库存 | 建议设计 |
| `qc_result` / `reject_reason` | 质检判定时写入 | 结果和原因不能只存备注，否则无法统计和追溯 | 支持质量异常分类 | 解释为什么被隔离或拒收 | 参考事实＋建议设计 |
| `disposition` | 主管或质检流程决定 | 不应默认“转次品”就是唯一处理方式 | 支持退供、返工和销毁 | 让不合格品有明确去向 | 建议设计＋待确认 |

### 4.3 上架任务 `putaway_task` / `putaway_line`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `putaway_task_id` | 上架任务标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `putaway_task_no` | 上架任务号 | 业务编号 | VARCHAR | 必填 |
| `source_record_id` | 来源收货/清点/质检记录 | 关联 ID | BIGINT/UUID | 必填 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `source_location_id` | 来源暂存库位 | 关联 ID | BIGINT/UUID | 可选，待确认 |
| `target_location_id` | 目标库位 | 关联 ID | BIGINT/UUID | 确认上架前必填 |
| `container_id` | 容器 | 关联 ID | BIGINT/UUID | 容器作业时必填 |
| `putaway_qty` | 应上架数量 | 数量 | DECIMAL | 必填 |
| `confirmed_qty` | 已上架数量 | 数量 | DECIMAL | 默认 0 |
| `status` | 上架状态 | 待上架/作业中/完成/关闭 | ENUM | 默认待上架 |
| `exception_reason` | 异常原因 | 原因编码/文本 | VARCHAR/ENUM | 异常时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `target_location_id` | 系统指导或人工确认时写入 | 推荐位置和实际位置必须分开，确认后才能作为库存定位 | 支持库位推荐准确率 | 防止账面位置与现场位置不一致 | 参考事实＋建议设计 |
| `putaway_qty` / `confirmed_qty` | 任务生成和现场确认更新 | 支持部分上架，未上架数量不能消失 | 支持上架效率和积压监控 | 解释收货完成但库位未完成 | 建议设计 |
| `container_id` | 扫描或装箱时写入 | 容器绑定、释放和库存归属必须可回溯 | 支持托盘和周转箱作业 | 解决容器内货物定位问题 | 参考事实＋建议设计 |
| `exception_reason` | 任务异常或关闭时写入 | 异常关单必须保留原因和剩余数量 | 支持异常任务池 | 防止任务被关闭后无人处理 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 有预约/无预约收货和清点 | 作业模式、来源、清点数量 | 覆盖常规到货和异常到货 |
| P0 | 批次、效期、序列号采集 | 商品属性、批次、序列号 | 按主数据规则启用 |
| P0 | 上架任务和实际库位确认 | 目标库位、应上架/已上架 | 闭合入库现场链路 |
| P1 | 质检、不合格处理和复检 | 质检结果、原因、处理决定 | 按业务启用，避免默认复杂化 |
| P1 | 容器化收货和上架 | 容器、箱内明细 | 支撑托盘、周转箱和箱码 |
| 后续 | 自动上架、设备协同和图像质检 | 设备任务、规则结果 | 条件能力，不写成通用必需字段 |

## 6. 跨模块依赖、拓展与待确认

- 读取入库预约、商品、批次/序列号规则和库位策略；上架确认后向库存余额和库存流水提供生效结果。
- 可拓展到质检隔离、供应商质量分析、容器交接、自动化上架和冷链/医药合规。
- 收货、质检、入库生效和上架生效的具体先后、无预约收货如何建立来源、质检不合格的库存属性和复检规则，均待确认。
