# 12 系统配置、权限与集成字段设计

> 参考范围：`01-按章节拆分的md文件/01-基础信息与系统设置.md`、`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`01-按章节拆分的md文件/03-仓内策略.md`、`01-按章节拆分的md文件/10-打印与电子面单.md`、`01-按章节拆分的md文件/12-报表与运维辅助.md`、`03-WMS产品设计精华知识借鉴/12-系统配置权限与集成设计.md`
> 字段编码、长度和数据库属性均为建议设计；平台和设备专属字段不默认纳入通用核心模型。

## 1. 本章范围

### 1.1 包含哪些模块

仓库与货主配置、账号、角色、菜单/动作权限、数据权限、审批中心、业务参数、ERP/OMS/WCS/设备对接、店铺与电子面单授权、异步接口日志和操作日志。

### 1.2 包含哪些功能

配置维护、权限控制、审批流、外部系统授权、消息接收、幂等校验、同步、失败重试、异常记录和操作审计。

### 1.3 业务场景与要解决的问题

本章解决多仓、多货主、多平台、多人和多设备环境下的安全运行与系统协同问题。参考资料出现角色管理、账号管理、审批中心、ERP/OMS、WCS、设备、店铺授权、电子面单授权、接口日志和操作日志。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 业务配置 | 保存仓库、货主和模块参数 | 按作用域生效 | P0 |
| 账号/角色/权限 | 控制菜单、动作和数据范围 | 账号 N:M 角色 | P0 |
| 审批流程/审批实例 | 控制高风险单据操作 | 流程 1:N 实例 | P1 |
| 接口消息/同步记录 | 保存外部请求和处理结果 | 消息 1:N 重试记录 | P0 |
| 授权配置 | 保存店铺、平台、面单等凭证引用 | 平台/店铺关联 | P1/条件采用 |
| 操作日志 | 保存用户和系统操作证据 | 对象 1:N 日志 | P0 |

## 3. 字段设计原则

- 配置必须有作用域：全局、仓库、货主、店铺或业务类型，不能只保存一个无归属参数。
- 菜单权限、动作权限和数据权限分开，能看不等于能操作，能操作也不等于能看全部数据。
- WMS 内部业务状态和外部同步状态分开，外部失败不能覆盖内部单据状态。
- 接口消息必须有外部单号、请求标识、幂等键、处理状态、失败原因和重试记录。
- 密钥、授权凭证和敏感收件信息不能按普通业务字段明文展示；具体脱敏和加密方式待确认。
- 操作日志记录“谁在何时对什么对象做了什么”，不能只保存页面访问日志。

## 4. 字段定义与设计说明

### 4.1 配置、账号和权限 `business_config` / `user` / `role`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `config_id` | 配置标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `config_key` | 配置编码 | 稳定键 | VARCHAR | 必填 |
| `scope_type` | 配置作用域类型 | 全局/仓库/货主/店铺 | ENUM | 必填 |
| `scope_id` | 配置作用域标识 | 关联 ID | BIGINT/UUID | 非全局时必填 |
| `config_value` | 配置值 | 文本/结构化值 | VARCHAR/JSON | 必填 |
| `effective_from` | 生效时间 | 日期时间 | DATETIME | 可选 |
| `status` | 配置状态 | 草稿/启用/停用 | ENUM | 默认启用或草稿，待确认 |
| `user_id` | 账号标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `role_id` | 角色标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `permission_code` | 权限编码 | 菜单/动作/数据权限 | VARCHAR | 必填 |
| `data_scope` | 数据范围 | 仓库/货主/店铺集合 | JSON/关联表 | 按权限必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `scope_type` / `scope_id` | 配置保存时写入 | 同一配置键在不同作用域的优先级必须明确 | 支持多仓和多货主差异化配置 | 避免一个仓库的配置影响全部仓库 | 建议设计 |
| `config_value` | 管理员维护时写入 | 字符串、数字、布尔和结构化配置要有类型校验 | 支持模块开关和参数化策略 | 避免配置值保存成功但运行解析失败 | 参考事实＋建议设计 |
| `permission_code` / `data_scope` | 角色配置时写入 | 菜单可见、动作可用和数据范围分别校验 | 支持岗位、临时授权和货主隔离 | 防止越权查看或操作 | 参考事实＋建议设计 |
| `status` / `effective_from` | 配置发布时更新 | 配置变更应知道何时影响新业务，历史业务是否受影响待确认 | 支持灰度和配置审计 | 降低开关误改风险 | 建议设计＋待确认 |

### 4.2 审批流程 `approval_flow` / `approval_instance`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `flow_id` | 审批流程标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `business_type` | 业务模块 | 入库/库存调整等 | ENUM/VARCHAR | 必填 |
| `document_type` | 单据类型 | 具体单据类型 | ENUM/VARCHAR | 必填 |
| `scope_id` | 适用仓库/货主 | 关联 ID | BIGINT/UUID | 按范围配置 |
| `approval_level` | 审批级数 | 正整数 | INT | 必填 |
| `approver_type` | 审批人类型 | 角色/账号 | ENUM | 必填 |
| `approver_id` | 审批人 | 关联 ID | BIGINT/UUID | 必填 |
| `instance_id` | 审批实例标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `document_id` | 来源单据 | 关联 ID | BIGINT/UUID | 必填 |
| `approval_status` | 审批状态 | 审批中/通过/驳回/撤销 | ENUM | 默认审批中 |
| `approval_comment` | 审批意见 | 文本 | TEXT | 可选 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `business_type` / `document_type` | 审批流程配置时写入 | 业务模块和单据类型不能只靠页面名称匹配 | 支持不同单据不同审批 | 让高风险操作进入正确审批流 | 参考事实＋建议设计 |
| `approval_level` / `approver_type` / `approver_id` | 流程发布时写入 | 多级审批、审批人去重和代理规则要明确 | 支持金额/货主/仓库差异化审批 | 控制库存调整和入库审核 | 参考事实＋待确认 |
| `approval_status` / `approval_comment` | 审批动作时更新 | 驳回、撤销和重新提交要保留历史实例 | 支持审计和重新发起 | 防止只保留最终结果 | 参考事实＋建议设计 |

### 4.3 接口消息与操作日志 `integration_message` / `operation_log`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `message_id` | 消息标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `system_code` | 外部系统 | ERP/OMS/WCS/平台等 | ENUM/VARCHAR | 必填 |
| `message_type` | 消息类型 | 商品/订单/入库/库存/发货等 | VARCHAR | 必填 |
| `external_no` | 外部业务单号 | 单号 | VARCHAR | 有业务对象时必填 |
| `request_id` | 请求标识 | 唯一请求号 | VARCHAR | 必填 |
| `idempotency_key` | 幂等键 | 唯一键 | VARCHAR | 必填，规则待确认 |
| `payload_ref` | 原始报文引用 | 文本或文件引用 | TEXT/VARCHAR | 按合规要求保存 |
| `sync_status` | 同步状态 | 待处理/成功/失败/重试中 | ENUM | 默认待处理 |
| `retry_count` | 重试次数 | 非负整数 | INT | 默认 0 |
| `error_code` | 错误编码 | 编码 | VARCHAR | 失败时可选 |
| `error_message` | 错误信息 | 文本 | TEXT | 失败时可选 |
| `operation_type` | 操作类型 | 新增/修改/审核/确认等 | ENUM/VARCHAR | 日志必填 |
| `operator_id` | 操作人/服务 | 用户或服务 ID | BIGINT/UUID/VARCHAR | 日志必填 |
| `operated_at` | 操作时间 | 日期时间 | DATETIME | 系统生成 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `system_code` / `message_type` / `external_no` | 接收或发送消息时写入 | 外部平台、业务类型和单号必须能定位消息边界 | 支持多系统状态映射 | 处理商品、订单和库存同步 | 参考事实＋建议设计 |
| `request_id` / `idempotency_key` | 请求生成时写入 | 幂等键不能只用时间戳；重复请求必须可判断 | 支持接口重试和消息去重 | 防止重复建单和重复回写 | 建议设计＋待确认 |
| `payload_ref` | 接收消息时保存 | 原始报文是排错和审计依据，敏感信息需脱敏/加密 | 支持接口回放和版本兼容 | 还原外部系统实际发送内容 | 建议设计＋待确认 |
| `sync_status` / `retry_count` / `error_message` | 处理和重试时更新 | 外部同步失败不能覆盖内部业务状态 | 支持失败队列和补偿 | 防止接口失败无从定位 | 参考事实＋建议设计 |
| `operation_type` / `operator_id` / `operated_at` | 用户或服务操作时写入 | 系统服务也要作为责任主体记录 | 支持审计、权限复盘和安全分析 | 知道谁在何时改变了对象 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 账号、角色、菜单/动作和数据权限 | 用户、角色、权限、范围 | 多仓多货主场景必须具备 |
| P0 | 业务配置和操作日志 | 作用域、值、状态、日志 | 保证配置可追踪 |
| P0 | 接口接收、幂等、失败记录 | 请求、幂等、状态、错误 | 防止重复建单和静默失败 |
| P1 | 审批流程和审批实例 | 业务类型、审批人、状态 | 按库存调整、入库等高风险场景启用 |
| P1 | 授权和电子面单配置 | 平台、店铺、凭证引用 | 作为平台适配能力，不污染交易核心 |
| 后续 | 全面配置中心、密钥轮换和设备编排 | 配置版本、密钥、设备 | 依赖安全和集成基础设施 |

## 6. 跨模块依赖、拓展与待确认

- 为所有业务单据、任务、库存和报表提供权限、配置、审批、同步和审计基础。
- 可拓展到多组织、多租户、货主自助、接口补偿、消息回放、设备集成和平台授权中心。
- 内外部状态映射、幂等键规则、原始报文保存期限、敏感字段脱敏和审批撤销后的业务影响，均待确认。
