# 13 公共字段与枚举基线

> 本文件统一各章节反复出现的公共字段、枚举和约束。字段编码均为建议编码，不代表万里牛真实数据库字段。
> 参考范围：`03-WMS产品设计精华知识借鉴/00-总体设计方法与跨模块基线.md` 及各章节对应的 `01` 操作手册。

## 1. 公共字段分组

### 1.1 身份与来源字段

| 字段编码（建议） | 字段名称 | 适用对象 | 设计关注点 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | 内部主键 | 所有持久化对象 | 只表达系统内部身份，不给现场人员使用 | 建议设计 |
| `code` | 内部编码/业务单号 | 主数据、单据、任务 | 编码规则和唯一范围必须按对象定义 | 建议设计 |
| `external_no` | 外部单号 | 同步单据、商品、接口消息 | 必须与外部系统编码和来源系统配合使用 | 参考事实＋建议设计 |
| `source_doc_no` | 来源单号 | 下游单据、任务、流水 | 表达业务来源，不等同于当前对象单号 | 归纳判断＋建议设计 |
| `source_line_no` | 来源明细行号 | 明细、流水 | 支持行级对账和回写 | 建议设计 |
| `source_type` | 来源对象类型 | 任务、匹配、日志 | 不能用单号格式猜来源类型 | 建议设计 |

### 1.2 组织与业务归属字段

| 字段编码（建议） | 字段名称 | 适用对象 | 设计关注点 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- |
| `warehouse_id` | 仓库 | 单据、任务、库存、策略 | 既是作业范围也是库存归属 | 参考事实＋建议设计 |
| `owner_id` | 货主 | 商品、单据、库存、权限 | 3PL 场景的核心数据隔离维度 | 参考事实＋归纳判断 |
| `store_id` | 店铺 | 电商订单、面单 | 订单来源和平台授权使用 | 参考事实＋建议设计 |
| `supplier_id` | 供应商 | 入库、商品主数据 | 采购来源和到货对账使用 | 参考事实＋建议设计 |
| `carrier_id` | 承运商 | 入库交接、包裹、运单 | 承运商资料和运单来源要分开 | 参考事实＋建议设计 |

### 1.3 审计与操作字段

| 字段编码（建议） | 字段名称 | 适用对象 | 设计关注点 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- |
| `created_by` / `created_at` | 创建人/创建时间 | 所有业务对象 | 记录首次产生责任 | 建议设计 |
| `updated_by` / `updated_at` | 修改人/修改时间 | 可修改对象 | 不能替代业务事件日志 | 建议设计 |
| `operator_id` | 操作人/执行服务 | 作业、流水、日志 | 区分人工账号、系统任务和接口服务 | 建议设计 |
| `effective_at` | 生效时间 | 库存事务、单据 | 是业务结果发生时间，不等于保存时间 | 建议设计 |
| `reason_code` | 原因编码 | 差异、取消、调整、异常 | 编码用于统计，备注用于补充 | 建议设计 |
| `remark` | 备注 | 多数业务对象 | 不能用备注替代关键结构化字段 | 参考事实＋建议设计 |

### 1.4 外部同步字段

| 字段编码（建议） | 字段名称 | 适用对象 | 设计关注点 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- |
| `system_code` | 外部系统编码 | 接口消息 | 区分 ERP、OMS、WCS、平台和设备 | 建议设计 |
| `request_id` | 请求标识 | 接口消息 | 用于定位一次请求，不一定等同于业务单号 | 建议设计 |
| `idempotency_key` | 幂等键 | 接口消息、业务创建 | 规则必须稳定且可重放 | 建议设计＋待确认 |
| `sync_status` | 同步状态 | 单据、库存、接口消息 | 与 WMS 内部业务状态分开 | 参考事实＋建议设计 |
| `retry_count` | 重试次数 | 异步任务、接口消息 | 重试前需判断是否产生副作用 | 建议设计 |
| `error_code` / `error_message` | 错误编码/错误信息 | 失败记录 | 编码统计和原始信息排查分开 | 建议设计 |

## 2. 公共枚举基线

以下是跨章节的建议字典。具体值要以目标系统确认，不把页面文字自动当成最终代码。

| 枚举名称 | 建议值 | 主要使用对象 | 说明 |
| :--- | :--- | :--- | :--- |
| 主数据状态 | `draft`、`enabled`、`disabled` | 商品、库位、承运商、策略 | 停用替代物理删除 |
| 单据状态 | `draft`、`pending`、`processing`、`partial`、`completed`、`cancelled`、`closed` | 入库、出库、盘点、调整 | 只表达业务单据生命周期 |
| 任务状态 | `pending`、`assigned`、`processing`、`partial`、`completed`、`failed`、`cancelled`、`unassigned` | 收货、上架、拣货、设备 | 只表达现场执行生命周期 |
| 库存属性 | `good`、`defective` | 库存、入库、出库、盘点 | 操作手册明确正品/次品场景，具体代码待确认 |
| 库位使用方式 | 拣选、箱拣选、存储、预配、异常暂存、过渡、工位、次品 | 库位 | 来源于操作手册，需确认最终编码 |
| 库位存储类型 | 普通、托盘 | 库位 | 托盘容器只能指导到托盘库位的约束需保留 |
| 同步状态 | `pending`、`processing`、`success`、`failed`、`retrying` | 接口、单据回写 | 不覆盖 WMS 内部状态 |
| 异常严重程度 | `info`、`warning`、`high`、`critical` | 监控事件 | 级别与处理状态分开 |
| 异常处理状态 | `unhandled`、`handling`、`resolved`、`ignored` | 监控、差异、接口 | “已发现”不等于“已解决” |
| 数量单位 | 件、箱、托、基本单位等 | 商品、单据、库存 | 单位字典和换算比例必须统一 |

## 3. 公共约束

| 约束类型 | 设计要求 | 主要影响 |
| :--- | :--- | :--- |
| 唯一性 | 业务单号、任务号、库位编码、条码、幂等键在明确作用域内唯一 | 防止重复建单和错误扫描 |
| 关联完整性 | 来源单据、来源行、任务和库存流水尽量保留关联 | 支持端到端追溯 |
| 数量一致性 | 计划量、完成量、差异量和库存数量不能互相覆盖 | 防止进度失真 |
| 状态合法性 | 状态只能通过合法动作迁移 | 防止跳过前置条件 |
| 删除策略 | 已被业务引用的对象采用停用或归档 | 保留历史数据 |
| 精度和单位 | 数量、重量、体积、金额分别定义精度和单位 | 防止换算和计费错误 |
| 敏感信息 | 收件地址、手机号、授权凭证和原始报文按权限脱敏 | 降低数据泄露风险 |

## 4. 待确认事项

1. 业务单号、外部单号和幂等键的唯一范围。
2. 状态枚举的最终代码、是否允许跳转和是否允许回退。
3. 数量、重量、体积和金额的小数精度及单位。
4. 软删除、归档和历史版本的技术实现。
5. 原始接口报文的保存期限、脱敏和加密要求。
