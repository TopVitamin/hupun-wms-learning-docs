# 10 任务管理字段设计

> 参考范围：`01-按章节拆分的md文件/01-基础信息与系统设置.md`、`01-按章节拆分的md文件/03-仓内策略.md`、`01-按章节拆分的md文件/04-入库操作.md`、`01-按章节拆分的md文件/05-出库_B2C.md`、`01-按章节拆分的md文件/06-大宗_B2B.md`、`01-按章节拆分的md文件/07-仓内作业.md`、`01-按章节拆分的md文件/10-打印与电子面单.md`、`03-WMS产品设计精华知识借鉴/10-任务管理设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

收货、上架、补货、拣货、复核、移库、盘点、加工、设备、打印和系统异步任务的统一任务生命周期。

### 1.2 包含哪些功能

任务创建、拆分、分派、领取、解绑、执行、部分完成、完成、失败、取消、重试和任务日志。

### 1.3 业务场景与要解决的问题

任务中心解决业务单据与现场执行之间的异步衔接问题。参考资料中存在系统任务、作业任务、设备任务和打印任务；拣货任务被领取后进入作业中，解绑后可重新领取，部分作业可以拆出新任务。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 任务主表 | 统一任务身份、来源和生命周期 | 业务对象 1:N 任务 | P0 |
| 任务明细 | 保存具体商品、库位、数量和执行结果 | 任务 1:N 明细 | P0 |
| 任务领取记录 | 保存领取、解绑和转交历史 | 任务 1:N 记录 | P0 |
| 任务日志 | 保存状态、失败和重试历史 | 任务 1:N 日志 | P0 |
| 任务依赖 | 保存前后置任务关系 | 任务 N:M 任务 | P1 |

## 3. 字段设计原则

- 业务单据状态表达业务意图，任务状态表达现场工作，库存生效状态由库存事务表达。
- 任务必须保留来源对象、任务类型、责任人、目标对象和数量进度。
- 解绑不是删除任务；领取历史、已做数量和异常原因必须保留。
- 重试必须区分“任务未执行”“执行失败”和“已产生部分副作用”，不能简单重新执行。
- 设备任务、打印任务和作业任务可以复用生命周期，但领域字段和成功条件要分开。

## 4. 字段定义与设计说明

### 4.1 任务主表 `task`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `task_id` | 任务标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `task_no` | 任务号 | 业务编号 | VARCHAR | 必填 |
| `task_type` | 任务类型 | 收货/上架/拣货/盘点/设备等 | ENUM | 必填 |
| `source_type` | 来源对象类型 | 单据/波次/预警/接口等 | ENUM | 必填 |
| `source_id` | 来源对象标识 | 关联 ID | BIGINT/UUID | 必填 |
| `warehouse_id` | 仓库 | 关联 ID | BIGINT/UUID | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 多货主必填 |
| `priority` | 任务优先级 | 正整数 | INT | 默认值待确认 |
| `assigned_to` | 当前领取人 | 用户 ID | BIGINT/UUID | 未领取时为空 |
| `status` | 任务状态 | 待领取/作业中/部分完成/完成/失败/取消 | ENUM | 默认待领取 |
| `retry_count` | 重试次数 | 非负整数 | INT | 默认 0 |
| `created_at` | 创建时间 | 日期时间 | DATETIME | 系统生成 |
| `started_at` | 开始时间 | 日期时间 | DATETIME | 领取时写入 |
| `completed_at` | 完成时间 | 日期时间 | DATETIME | 完成时写入 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `task_type` / `source_type` / `source_id` | 策略或业务单据生成任务时写入 | 任务类型和来源类型不能混为一个字段 | 支持统一任务中心和来源回溯 | 解释任务为什么产生 | 建议设计 |
| `assigned_to` / `status` | 领取、解绑、提交时更新 | 解绑后应释放当前责任，但不抹掉领取历史 | 支持多人协作和绩效 | 避免任务重复执行 | 参考事实＋建议设计 |
| `priority` | 策略或任务调度时写入 | 优先级需要有稳定排序和人工干预边界 | 支持紧急任务和异常插队 | 让作业先后可控 | 建议设计 |
| `retry_count` | 失败重试时递增 | 重试前要判断是否已经产生库存、打印或设备副作用 | 支持接口和设备失败补偿 | 防止重复记账或重复打印 | 建议设计 |
| `started_at` / `completed_at` | 领取和完成时写入 | 作业时长应基于任务时间，不用报表查询时间代替 | 支持绩效和 SLA | 衡量现场处理效率 | 建议设计 |

### 4.2 任务明细与领取历史 `task_line` / `task_assignment`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `task_line_id` | 任务明细标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `task_id` | 任务 | 关联 ID | BIGINT/UUID | 必填 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 业务任务必填 |
| `source_location_id` | 来源库位 | 关联 ID | BIGINT/UUID | 取货任务必填 |
| `target_location_id` | 目标库位 | 关联 ID | BIGINT/UUID | 上架/移库任务必填 |
| `planned_qty` | 计划数量 | 数量 | DECIMAL | 必填 |
| `completed_qty` | 已完成数量 | 数量 | DECIMAL | 默认 0 |
| `exception_qty` | 异常数量 | 数量 | DECIMAL | 默认 0 |
| `assignment_id` | 领取记录标识 | 统一 ID | BIGINT/UUID | 领取时生成 |
| `operator_id` | 操作人 | 用户 ID | BIGINT/UUID | 必填 |
| `assigned_at` | 领取时间 | 日期时间 | DATETIME | 系统生成 |
| `unassigned_at` | 解绑时间 | 日期时间 | DATETIME | 解绑后写入 |
| `assignment_reason` | 领取/解绑原因 | 原因编码/文本 | VARCHAR/ENUM | 异常时可选 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `planned_qty` / `completed_qty` / `exception_qty` | 任务生成、现场提交和异常处理时更新 | 部分完成要保留剩余和异常数量 | 支持补任务和进度监控 | 防止任务完成但数量不完整 | 建议设计 |
| `source_location_id` / `target_location_id` | 任务生成或现场确认时写入 | 目标位置和实际位置可能不同，需保留确认结果 | 支持库位准确率和路径分析 | 追溯货物实际移动 | 建议设计 |
| `assignment_id` / `operator_id` | 每次领取生成记录 | 一个任务可被多人先后领取，但同一时刻责任人规则待确认 | 支持计件和责任追踪 | 解决任务解绑后无人负责 | 参考事实＋建议设计 |
| `assignment_reason` | 解绑、转交或异常时写入 | 原因可分类才有管理价值 | 支持异常任务分析 | 解释为什么任务反复流转 | 建议设计 |

### 4.3 任务日志与依赖 `task_log` / `task_dependency`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `task_log_id` | 日志标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `task_id` | 任务 | 关联 ID | BIGINT/UUID | 必填 |
| `from_status` | 原状态 | 状态值 | ENUM/VARCHAR | 必填 |
| `to_status` | 新状态 | 状态值 | ENUM/VARCHAR | 必填 |
| `event_type` | 事件类型 | 领取/提交/失败/重试等 | ENUM | 必填 |
| `error_code` | 错误编码 | 编码 | VARCHAR | 异常时可选 |
| `error_message` | 错误信息 | 文本 | TEXT | 异常时可选 |
| `occurred_at` | 发生时间 | 日期时间 | DATETIME | 系统生成 |
| `predecessor_task_id` | 前置任务 | 关联 ID | BIGINT/UUID | 有依赖时必填 |
| `dependency_type` | 依赖类型 | 完成后才能执行等 | ENUM | 有依赖时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `from_status` / `to_status` / `event_type` | 任务状态变更时写入 | 状态变更必须有合法事件，不能只覆盖当前状态 | 支持任务审计和问题复盘 | 解释任务如何走到当前状态 | 建议设计 |
| `error_code` / `error_message` | 失败或异常时写入 | 编码用于统计，原始信息用于排查 | 支持自动重试和异常分派 | 区分库存、设备、接口和人工异常 | 建议设计 |
| `predecessor_task_id` / `dependency_type` | 任务生成时写入 | 前后置任务不能只靠名称约定 | 支持收货—质检—上架、拣货—复核链路 | 防止前置未完成就执行后置任务 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 统一任务身份、来源和状态 | 任务类型、来源、状态 | 所有作业任务共用生命周期 |
| P0 | 领取、解绑和责任追踪 | 领取人、领取历史 | 支撑多人协同 |
| P0 | 数量进度、部分完成和异常 | 计划/完成/异常量 | 防止任务假完成 |
| P0 | 失败、重试和日志 | 错误、重试次数、日志 | 支撑可恢复运行 |
| P1 | 任务依赖和调度优先级 | 前置任务、优先级 | 支撑复杂作业链 |
| 后续 | 智能派工、动态路线和设备编排 | 算法、设备字段 | 在基础任务模型稳定后扩展 |

## 6. 跨模块依赖、拓展与待确认

- 任务来源于策略、入库、出库、库存交易、盘点、打印和设备；任务完成结果回写来源单据和库存流水。
- 可拓展到人员技能、工作量计件、设备接管、超时升级、任务池和 SLA 监控。
- 任务部分完成后的拆分方式、同时领取限制、失败重试的幂等边界和库存锁定释放时机，均待确认。
