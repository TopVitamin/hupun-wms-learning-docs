# 06 出库管理字段设计

> 参考范围：`01-按章节拆分的md文件/05-出库_B2C.md`、`01-按章节拆分的md文件/06-大宗_B2B.md`、`01-按章节拆分的md文件/09-特殊作业与即时零售.md`、`03-WMS产品设计精华知识借鉴/06-出库管理设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

B2C 电商订单、大宗 B2B 出库、特殊出库模式、出库单、订单明细、包裹和发运关联。

出库执行中的波次、拣货、复核、打包和称重在本目录的 07 章展开；本章负责表达“要发什么、发给谁、发运结果是什么”。

### 1.2 包含哪些功能

订单接收、订单审核、出库单创建、库存分配、拆单、取消、部分出库、包裹生成、运单关联、发货和外部状态回传。

### 1.3 业务场景与要解决的问题

出库管理解决订单从外部渠道进入仓库后，无法区分来源、货主、商品需求和履约进度的问题。字段要能区分订单需求数量、分配数量、拣货数量、发货数量和包裹数量，支撑缺货、部分发货、多包裹和平台特殊订单。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 出库订单/发货单 | 表达外部或内部发货意图 | 头 1:N 明细 | P0 |
| 出库明细 | 表达 SKU 级需求和履约进度 | 被分配、拣货和发运引用 | P0 |
| 包裹 | 表达一次实际包装和发运载体 | 订单 1:N 包裹 | P0 |
| 运单关联 | 表达承运商和物流单号 | 包裹 0:1 或 1:N 运单 | P0/P1 |
| 订单来源关联 | 保存平台、店铺和外部订单信息 | 订单引用主数据 | P0 |

## 3. 字段设计原则

- 内部出库单号、外部订单号、平台订单号和包裹号分开保存。
- 订单需求、库存分配、拣货、复核和发货是不同进度，不能用一个数量覆盖。
- 订单状态表达业务是否允许继续处理，任务状态由 07 章表达现场执行进度。
- 地址、商品名称、规格和收件信息属于履约快照，外部资料变更后不能无痕覆盖历史发运凭证。
- 运单号和承运商可能由平台指定，也可能由 WMS 申请；来源和可修改性必须明确。

## 4. 字段定义与设计说明

### 4.1 出库订单头 `outbound_order`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `outbound_order_id` | 出库订单标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `outbound_order_no` | 出库单号 | 内部业务单号 | VARCHAR | 必填 |
| `external_order_no` | 外部订单号 | 平台/ERP 单号 | VARCHAR | 对接场景必填 |
| `source_platform_code` | 订单来源平台 | 平台编码 | VARCHAR/ENUM | 对接场景必填 |
| `order_type` | 订单类型 | B2C/B2B/特殊类型 | ENUM | 必填 |
| `warehouse_id` | 发货仓库 | 关联 ID | BIGINT/UUID | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 多货主必填 |
| `store_id` | 店铺 | 关联 ID | BIGINT/UUID | 电商订单必填 |
| `order_at` | 下单时间 | 日期时间 | DATETIME | 外部订单必填 |
| `status` | 出库业务状态 | 待审核/待分配/作业中/已发货/取消等 | ENUM | 默认待处理 |
| `carrier_id` | 承运商 | 关联 ID | BIGINT/UUID | 发运前可选 |
| `waybill_no` | 运单号 | 承运商单号 | VARCHAR | 获取运单后写入 |
| `shipped_at` | 发货时间 | 日期时间 | DATETIME | 发货后写入 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `external_order_no` | ERP/平台推送 | 必须配合来源平台和店铺确定唯一范围 | 支持接口幂等和平台回传 | 防止同一订单重复创建 | 参考事实＋建议设计 |
| `order_type` | 接单或审核时识别 | B2C、B2B 和特殊模式的作业链不同 | 支持即时零售、JIT/JITX 等扩展 | 让订单进入正确的执行路径 | 参考事实＋建议设计 |
| `warehouse_id` / `owner_id` / `store_id` | 接单匹配主数据 | 货主、店铺、仓库必须互相授权 | 支持多仓、多货主和店铺数据隔离 | 防止错仓发货和数据越权 | 归纳判断＋建议设计 |
| `status` | 审核、分配、发货和取消动作更新 | 业务状态不能代替拣货任务状态或库存数量 | 支持订单拦截和异常池 | 控制下一步可执行动作 | 参考事实＋建议设计 |
| `carrier_id` / `waybill_no` | 申请面单、手工录入或平台回传 | 平台指定承运商时不应允许人工修改 | 支持物流跟踪和承运商对账 | 确保发运结果可追踪 | 参考事实＋待确认 |

### 4.2 出库明细 `outbound_order_line`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `outbound_line_id` | 出库明细标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `outbound_order_id` | 出库订单 | 关联 ID | BIGINT/UUID | 必填 |
| `line_no` | 明细行号 | 正整数 | INT | 系统生成 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `ordered_qty` | 订单需求数量 | 数量＋单位 | DECIMAL | 必填 |
| `allocated_qty` | 已分配数量 | 数量 | DECIMAL | 默认 0 |
| `picked_qty` | 已拣货数量 | 数量 | DECIMAL | 默认 0 |
| `shipped_qty` | 已发货数量 | 数量 | DECIMAL | 默认 0 |
| `unit_code` | 需求单位 | 单位编码 | VARCHAR | 必填 |
| `inventory_attr` | 库存属性 | 正品/次品等 | ENUM | 默认正品，待确认 |
| `lot_no` | 出库批次 | 批次号 | VARCHAR | 按规则必填 |
| `serial_no` | 序列号 | 唯一序列号 | VARCHAR | 序列号商品按件记录 |
| `shortage_qty` | 缺货数量 | 数量 | DECIMAL | 默认 0 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `ordered_qty` | 外部订单推送或人工创建 | 原始需求不能被后续履约数量覆盖 | 支持订单履约率统计 | 保留客户真正需要的数量 | 参考事实＋建议设计 |
| `allocated_qty` / `picked_qty` / `shipped_qty` | 分配、拣货和发货节点更新 | 三种进度必须单调且可解释，异常时保留差异 | 支持缺货分析和作业绩效 | 防止“已发货”与实际作业不一致 | 建议设计 |
| `unit_code` | 订单接收或换算时写入 | 订单单位和库存基本单位之间必须有换算 | 支持整箱出库和散件补足 | 避免数量换算错误 | 参考事实＋建议设计 |
| `lot_no` / `serial_no` | 分配或现场拣货时确定 | 是否允许人工指定批次、序列号需按商品规则控制 | 支持先进先出和售后追溯 | 确保发出的是正确库存身份 | 参考事实＋建议设计 |
| `shortage_qty` | 分配失败或拣货报缺时写入 | 缺货不能直接把需求量改小 | 支持补发、取消或异常处理 | 保留订单缺货责任 | 归纳判断＋建议设计 |

### 4.3 包裹与运单 `package` / `shipment`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `package_id` | 包裹标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `package_no` | 包裹号 | 业务编号 | VARCHAR | 系统生成 |
| `outbound_order_id` | 出库订单 | 关联 ID | BIGINT/UUID | 必填 |
| `package_qty` | 包裹数量 | 数量 | DECIMAL/INT | 默认 1 |
| `gross_weight` | 包裹毛重 | 数值＋单位 | DECIMAL | 称重场景写入 |
| `carrier_id` | 承运商 | 关联 ID | BIGINT/UUID | 发运时必填 |
| `waybill_no` | 运单号 | 字符串 | VARCHAR | 发运后必填 |
| `package_status` | 包裹状态 | 待打包/已称重/已发运等 | ENUM | 默认待处理 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `package_no` | 打包时生成 | 多包裹时必须能回到同一出库订单和明细 | 支持拆包、补打和物流查询 | 解决一个订单多个包裹难追踪 | 建议设计 |
| `gross_weight` | 称重时写入 | 要明确毛重/净重、单位和修改权限 | 支持计费、异常拦截和承运商对账 | 防止重量错误造成运费异常 | 参考事实＋待确认 |
| `waybill_no` | 平台或承运商返回 | 申请失败不能写成已发运；指定运单不可随意修改 | 支持物流跟踪和平台回传 | 保证发货凭证一致 | 参考事实＋建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 订单接收、审核和出库单 | 来源单号、仓库、货主、状态 | 支撑订单进入 WMS 并可追溯 |
| P0 | 明细数量进度 | 需求、分配、拣货、发货数量 | 防止只用一个“完成数量”造成状态失真 |
| P0 | 取消、缺货和部分出库 | 缺货量、取消原因、发货量 | 覆盖真实异常，不强行要求一次完成 |
| P0 | 包裹、承运商和运单 | 包裹号、重量、运单号 | 支撑发运结果和物流追踪 |
| P1 | B2B、大宗和特殊订单类型 | 订单类型、平台来源 | 按业务需要启用，不改变核心订单身份模型 |
| 后续 | 平台专属扩展字段 | 平台属性、扩展 JSON | 作为平台适配层，不污染通用字段 |

## 6. 跨模块依赖、拓展与待确认

- 读取商品、条码、包装、货主、店铺和承运商主数据；调用库存分配；由 07 章执行拣货、复核、包装和称重。
- 可拓展到多仓拆单、多包裹、即时零售、平台直配、JIT/JITX 和 3PL 货主计费。
- 平台订单唯一键、部分发货回传、多包裹运单关系、平台指定承运商的修改规则，均待确认。
