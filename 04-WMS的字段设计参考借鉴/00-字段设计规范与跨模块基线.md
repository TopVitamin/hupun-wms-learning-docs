# 00 字段设计规范与跨模块基线

## 1. 文档目的

本文件定义 04 目录的统一整理方法。它只规定如何读取资料、如何表达字段和如何标记判断，不代替各章节的具体字段设计。

## 2. 资料与事实边界

### 2.1 资料分工

- `00-源文件/`：原始资料，负责事实追溯。
- `01-按章节拆分的md文件/`：按业务主题定位操作、页面、字段名称和规则。
- `03-WMS产品设计精华知识借鉴/`：通用 WMS 的对象、流程和设计判断。
- 本目录：在上述资料基础上整理字段模型，并明确哪些内容是个人判断。

### 2.2 事实级别

| 标记 | 含义 | 写法要求 |
| :--- | :--- | :--- |
| 参考事实 | 原文明确出现的字段、页面、动作或规则 | 标注原始文件和小节 |
| 归纳判断 | 从多个页面或流程中归纳出的字段用途 | 说明推导依据，不写成原文原话 |
| 建议设计 | 为通用 WMS 建模提出的字段或规则 | 明确“建议”二字 |
| 待确认 | 资料不足或存在多种合理方案 | 保留问题，不擅自补全 |

## 3. 字段设计的统一结构

每个逻辑表至少包含以下内容：

1. 表/对象用途；
2. 记录创建和生效时机；
3. 与上游、下游对象的关系；
4. 字段定义表；
5. 字段设计说明表；
6. 业务场景与问题补充；
7. 跨模块依赖和待确认事项。

## 4. 字段定义表

字段定义表只放相对稳定的技术属性，避免业务解释过长：

| 字段编码 | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| 待填写 | 待填写 | 待确认 | 待确认 | 待确认 |

如果没有原始数据字典，字段编码和类型必须写成建议值，并在字段设计说明中标记为“建议设计”。

## 5. 字段设计说明表

字段设计说明表负责承载业务判断：

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待确认 |

“设计关注点”回答该字段如何支撑当前核心业务；“拓展用途”只写有明确价值的后续用途，不为了完整而扩展；“业务场景/解决问题”要说明字段缺失会造成什么业务后果。

## 6. 字段命名和类型规则

- 原始字段编码存在时，保留原编码，不擅自改名。
- 原始资料只有中文字段名称时，可以提出英文编码，但必须标记为“建议编码”。
- `字段格式/长度` 描述长度、精度、编码格式或枚举范围；`数据类型/数据库属性` 描述字符、整数、小数、日期时间、布尔、枚举等类型，不能混为一列。
- 金额、数量、重量、体积、比例和时间必须分别说明精度、单位和时区要求；资料没有说明时标记待确认。
- 状态字段要说明状态含义、进入条件和可执行动作，不能只列一个枚举值。
- 外部单号、来源单号、业务单号和内部主键要分开，不能用一个“单号”字段承担全部关联。

## 7. 跨模块字段基线

优先检查以下字段是否能贯穿业务闭环：

| 字段组 | 需要解决的问题 |
| :--- | :--- |
| 组织归属 | 仓库、货主、店铺和业务范围是否明确 |
| 商品身份 | SKU、条码、单位、包装和批次属性是否一致 |
| 空间定位 | 区域、库区、库位、容器和工位是否可追溯 |
| 数量进度 | 计划量、实收量、分配量、作业量和生效量是否区分 |
| 库存状态 | 实际、可用、锁定、冻结和在途是否混淆 |
| 来源关联 | 上游单据、来源明细、执行任务和库存流水是否关联 |
| 审计追溯 | 操作人、操作时间、原因和修改记录是否保留 |
| 外部同步 | 外部单号、同步状态、请求标识、失败原因和重试是否可查 |

## 8. 字段生成时机

每个字段都应尽量说明由谁在什么时机写入：

- 创建时生成；
- 外部系统推送时写入；
- 规则计算时生成；
- 现场扫描或人工录入时写入；
- 单据生效时写入；
- 逆向处理或异常处理时补写。

资料没有说明写入时机时，不根据页面显示位置推断数据库写入时机。

## 9. 业务场景拓展规则

拓展内容可以覆盖多货主、批次效期、序列号、箱规多单位、3PL、自动化设备、平台订单和外部接口等场景，但必须说明：

1. 它解决的具体问题；
2. 依赖哪些字段或对象；
3. 是通用能力、条件能力还是后置能力；
4. 当前资料是否已有依据。

## 10. 章节完成验收

- 章节包含模块、功能、逻辑表、字段和业务场景五类内容；
- 每个字段都有编码、名称、格式、数据类型和设计说明；
- 原始字段和建议字段没有混写；
- 关键数量、状态和来源关系没有混淆；
- 字段说明能回到操作手册或明确标注判断依据；
- 未说明的规则统一进入“待确认事项”；
- 章节内部链接、表头和 Markdown 围栏完整。
