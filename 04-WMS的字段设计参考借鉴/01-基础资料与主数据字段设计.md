# 01 基础资料与主数据字段设计

> 参考范围：`01-按章节拆分的md文件/01-基础信息与系统设置.md`、`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`01-按章节拆分的md文件/11-客服与财务.md`、`03-WMS产品设计精华知识借鉴/01-基础资料与主数据设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

商品主档、商品条码、计量单位、包装规格、批次/效期/序列号属性、货主、供应商、承运商和店铺关系。

### 1.2 包含哪些功能

商品新增、导入、ERP/OMS 同步、条码维护、多单位换算、箱规维护、主数据启停和引用校验。

### 1.3 业务场景与要解决的问题

主数据解决“同一商品重复录入”“扫描无法识别”“不同货主商品串用”和“历史单据因删除档案而断链”等问题。批次、效期和序列号属性进一步解决库存追溯和出库校验问题。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 商品主档 | 保存 SKU 的稳定身份和基础属性 | 被条码、库存、单据引用 | P0 |
| 商品条码 | 将扫描码映射到商品和单位 | 商品 1:N 条码 | P0 |
| 商品单位/包装 | 保存单位换算和箱规 | 商品 1:N 单位/包装 | P0/P1 |
| 货主/店铺 | 隔离业务归属和订单来源 | 货主 1:N 店铺 | P0 |
| 供应商/承运商 | 支撑入库来源和发运履约 | 被入库/出库引用 | P0 |
| 批次/序列号规则 | 声明属性采集和追溯要求 | 商品关联交易和库存 | P0/P1 |

## 3. 字段设计原则

- 商品身份、外部编码、条码和单位不能用一个字段混代。
- 货主是 3PL 场景的重要隔离维度，但是否进入商品唯一键需结合目标业务确认。
- 批次、效期、序列号管理方式一旦被库存或未完成单据使用，不应直接切换。
- 已被单据、库存或流水引用的主数据采用停用，不物理删除。
- 原始手册出现的是页面字段和业务规则，不等同于数据库字段；建议编码需单独标记。

## 4. 字段定义与设计说明

### 4.1 商品主档 `product`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `product_id` | 商品内部标识 | 统一 ID | BIGINT/UUID | 必填，系统生成 |
| `product_code` | 商品编码/SKU | 货主范围内编码 | VARCHAR，长度待确认 | 必填 |
| `product_name` | 商品名称 | 文本 | VARCHAR，长度待确认 | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 单货主可默认，多货主必填 |
| `base_unit_code` | 基本单位 | 枚举或单位编码 | VARCHAR | 必填 |
| `lot_manage_flag` | 批次管理标记 | `Y/N` | BOOLEAN/ENUM | 默认 `N` |
| `expiry_manage_flag` | 效期管理标记 | `Y/N` | BOOLEAN/ENUM | 默认 `N` |
| `serial_manage_flag` | 序列号管理标记 | `Y/N` | BOOLEAN/ENUM | 默认 `N` |
| `status` | 主数据状态 | 启用/停用 | ENUM | 默认草稿或启用，待确认 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `product_code` | 手工、导入或外部同步建档 | 必须稳定；改编码会影响条码、单据、库存和接口映射 | 可增加多系统编码映射 | 防止同一商品被重复建档 | 参考事实＋建议设计 |
| `owner_id` | 建档时选择或同步匹配 | 需要与仓库授权、订单货主和库存货主一致 | 支持多货主共仓和数据权限 | 防止串货和越权查询 | 归纳判断＋建议设计 |
| `lot_manage_flag` / `expiry_manage_flag` / `serial_manage_flag` | 建档时配置 | 影响库存维度和现场采集；手册明确相关管理变更存在清库存限制 | 支持食品、医药、设备追溯 | 解决批次、效期和序列号追溯 | 参考事实＋建议设计 |
| `status` | 管理员操作 | 停用只影响新业务引用，历史记录仍保留 | 支持生效审核和版本化 | 避免直接删除造成历史断链 | 归纳判断＋建议设计 |

### 4.2 商品条码 `product_barcode`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `barcode_id` | 条码记录标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `product_id` | 商品 | 关联商品 | BIGINT/UUID | 必填 |
| `barcode` | 条码 | 扫描字符 | VARCHAR，长度待确认 | 必填 |
| `barcode_type` | 条码类型 | 主条码/辅助码/箱码/单位码 | ENUM | 必填 |
| `unit_code` | 对应单位 | 单位编码 | VARCHAR | 单位条码时必填 |
| `is_primary` | 是否主条码 | `Y/N` | BOOLEAN | 默认 `N` |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `barcode` | 商品建档或同步 | 唯一范围必须明确，不能仅靠商品名称匹配 | 支持平台条码、箱码和外箱码 | 扫码收货、拣货、复核和盘点 | 参考事实＋建议设计 |
| `barcode_type` | 维护条码时选择 | 条码类型决定扫描后数量和单位换算 | 可扩展 GS1 或外部平台码 | 避免箱码按单件数量入库 | 建议设计＋待确认 |
| `unit_code` | 条码关联单位时写入 | 必须能反查换算比例 | 支持多级包装扫描 | 解决箱、件、散件口径不一致 | 参考事实＋建议设计 |

### 4.3 单位与包装 `product_unit` / `pack_spec`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `unit_code` | 单位编码 | 单位字典编码 | VARCHAR | 必填 |
| `unit_name` | 单位名称 | 文本 | VARCHAR | 必填 |
| `conversion_rate` | 与基本单位换算比例 | 正数，可含小数 | DECIMAL，精度待确认 | 基本单位为 1 |
| `is_default_box` | 是否默认箱单位 | `Y/N` | BOOLEAN | 默认 `N` |
| `pack_code` | 包装规格编码 | 编码 | VARCHAR | 使用箱规时必填 |
| `pack_qty` | 包装内数量 | 非负数量 | DECIMAL | 使用箱规时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `conversion_rate` | 商品单位维护 | 比例、舍入和库存基本单位必须统一 | 支持采购单位、拣货单位和箱单位 | 防止数量换算错误 | 参考事实＋建议设计 |
| `is_default_box` | 仓库/商品配置 | 只用于展示或换算时不能改变库存基本单位 | 支持库存按箱展示和快速出库 | 提高整箱作业效率 | 参考事实＋待确认 |
| `pack_qty` | 箱规维护 | 箱规变更要考虑已有箱库存和历史装箱记录 | 支持装箱、波次和耗材推荐 | 解决整箱与散件拣选问题 | 参考事实＋建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 商品、条码、单位、货主档案 | 商品身份、条码、货主、基本单位 | 必须稳定，否则所有交易模块无法闭环 |
| P0 | 启用/停用与引用校验 | `status`、引用关系 | 采用停用替代物理删除 |
| P0 | 批次、效期、序列号规则 | 三类管理标记 | 作为可配置能力，按商品需要启用 |
| P1 | 导入和外部同步 | 外部编码、导入批次、失败原因 | 先保证失败可见和可重试 |
| P1 | 多单位、箱规和箱码 | 换算比例、包装数量 | 先支持基本换算，复杂包装层级待确认 |
| 后续 | 医药追溯和平台扩展属性 | 扩展属性 | 作为行业/平台插件，不默认进入核心模型 |

## 6. 跨模块依赖、拓展与待确认

- 入库读取商品、条码、单位和批次属性；出库读取可拣货条码、包装和序列号规则；库存读取商品身份和库存属性。
- 可拓展到食品效期、医药追溯、设备序列号、3PL 多货主和外部 ERP/OMS 映射。
- 商品编码与外部编码是否一一对应、条码唯一范围、单位换算舍入、商品属性变更的审批和生效时机，均待确认。
