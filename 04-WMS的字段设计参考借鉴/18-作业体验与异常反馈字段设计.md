# 18 作业体验与异常反馈字段设计

> 本文是通用建议字段模型，参考收货匹配、波次报缺、补货、盘点、打印和接口异常等原始内容，不代表万里牛真实数据库字段。

## 1. 设计目标

现场页面要能在一次操作中表达：当前处理对象、应做数量、已做数量、异常原因、下一步动作和提交后的系统结果。为此，体验字段不能只放在页面组件里，应有可追溯的数据承载。

## 2. 作业反馈字段

| 字段编码（建议） | 字段名称 | 类型 | 写入时机 | 设计用途与校验 |
|---|---|---|---|---|
| `operation_object_type` / `operation_object_id` | 当前作业对象类型/标识 | ENUM/ID | 领取或打开任务 | 页面始终显示当前单据、任务、容器或包裹 |
| `required_qty` | 应作数量 | DECIMAL | 任务生成 | 不因现场短拣直接覆盖；作为数量守恒基准 |
| `completed_qty` | 已完成数量 | DECIMAL | 扫描或提交 | 由现场结果累计，不能大于应作数量，特殊加工场景另按规则确认 |
| `remaining_qty` | 剩余数量 | DECIMAL | 每次结果提交 | 建议由应作量减已完成量计算，不能与历史结果脱节 |
| `difference_qty` | 差异数量 | DECIMAL | 报缺、盘点或质检 | 明确是实盘减盘前、还是应作减实作，按场景分别定义 |
| `expected_value` / `actual_value` | 期望值/实际值 | VARCHAR/JSON | 扫描校验 | 支持商品、库位、容器、运单等不同校验对象 |
| `next_action_code` | 下一步动作 | ENUM | 校验或异常产生 | 如重扫、选择匹配、报缺、补货、释放、重试、作废、转人工 |
| `operator_message` | 面向操作员的提示 | TEXT | 校验或提交时生成 | 提示语应能解释对象、原因和动作，不替代结构化原因 |

## 3. 异常与恢复字段

| 字段编码（建议） | 字段名称 | 类型 | 必填条件 | 下游影响 |
|---|---|---|---|---|
| `exception_id` / `exception_type` | 异常标识/类型 | ID/ENUM | 异常产生时 | 进入异常队列并关联来源对象 |
| `exception_reason_code` | 异常原因编码 | ENUM | 异常产生时 | 支持统计、筛选和规则处理，不能只存备注 |
| `exception_detail` | 异常说明 | TEXT | 需要补充时 | 保存现场补充信息，不替代原因编码 |
| `exception_status` | 异常处理状态 | ENUM：未处理/处理中/已恢复/已关闭 | 系统默认 | “提醒关闭”不能自动代表业务事实已恢复 |
| `recovery_action` | 恢复动作 | ENUM | 处理异常时 | 记录重试、释放、补货、重锁、作废、转派或人工接管 |
| `original_operation_id` | 原作业记录 | ID | 重试/纠正时 | 新结果关联原记录，防止重复生效 |
| `retry_count` / `last_retry_at` | 重试次数/最后重试时间 | INT/DATETIME | 可重试异常 | 支持接口、打印和设备问题的运维判断 |
| `failure_code` / `failure_message` | 失败码/失败信息 | VARCHAR/TEXT | 失败时 | 保留外部或设备返回，便于重试和定位 |
| `handled_by` / `handled_at` | 处理人/处理时间 | ID/DATETIME | 异常处理时 | 支持责任追溯 |

## 4. 设计校验

| 场景 | 必须保持的字段关系 |
|---|---|
| 扫码匹配 | `expected_value`、`actual_value`、校验结果和下一步动作同时保留；多匹配时不能只记最终选择 |
| 拣货报缺 | `required_qty = completed_qty + shortage_qty + remaining_qty` 的口径需按任务定义确认，不能直接把应拣数量改小 |
| 盘点差异 | `difference_qty` 要注明盘前量和实盘量，库存调整是后续动作，不与盘点结果混成一个字段 |
| 打印/接口失败 | 原对象、失败信息、重试次数和最终结果要可关联；重试成功不能生成重复业务结果 |
| 补货任务 | 来源库位、目标库位、已补量、剩余量和关闭原因要同时存在，强制完成不能让未补数量消失 |

## 5. 验收问题

- 页面提示中的“下一步”是否有结构化字段支撑，还是只能依赖文案？
- 同一个异常重试多次后，能否看到每次结果以及最后一次是否真正生效？
- 任务关闭时，剩余数量、释放结果和关闭原因是否都可查询？
- 现场反馈字段是否与任务、库存流水、业务单据和接口日志共用稳定关联键？
- 是否把“页面展示状态”和“领域业务状态”错误地设计成同一个字段？
