# 08 库存管理字段设计

> 参考范围：`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`01-按章节拆分的md文件/07-仓内作业.md`、`01-按章节拆分的md文件/08-库存管理.md`、`01-按章节拆分的md文件/12-报表与运维辅助.md`、`03-WMS产品设计精华知识借鉴/08-库存管理设计.md`
> 字段编码、长度和数据库属性均为建议设计；库存数量定义依据操作手册明确内容整理。

## 1. 本章范围

### 1.1 包含哪些模块

库存总量、库位库存、历史库存、可接单库存、作业中库存、容器中商品、库存预警、库存差异量和库存明细追溯。

库存移动、盘点和库存调整的交易单据在 09 章展开；本章负责定义库存余额和查询视图如何表达。

### 1.2 包含哪些功能

库存汇总查询、库位明细查询、批次/序列号查询、实际/可用/锁定/冻结/在途数量展示、历史快照、预警、差异识别和库存流水追溯。

### 1.3 业务场景与要解决的问题

操作手册明确库存总量包含实际、可用、锁定、冻结和在途库存；库位库存可查看实际、可用、锁定和冻结，并能追溯库存变化和相关单据。字段设计要解决“账面总量和库位明细对不上”“可用库存被重复分配”“冻结库存被误发”和“批次/序列号无法定位”等问题。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 库存余额 | 保存某一库存维度下的当前数量 | 按仓库、库位、SKU 等维度聚合 | P0 |
| 库存总量视图 | 按仓库、货主或商品汇总余额 | 由余额和在途数据汇总 | P0 |
| 库存流水 | 保存每次库存变化和来源 | 余额 1:N 流水 | P0 |
| 历史库存快照 | 保存指定时点库存 | 由日终或业务快照生成 | P1 |
| 库存预警 | 保存上下限和触发结果 | 商品/库区/区域关联 | P1 |
| 库存差异/调整记录 | 保存账面差异和处理结果 | 与流水和调整单关联 | P0/P1 |

## 3. 字段设计原则

- “实际库存”“可用库存”“锁定库存”“冻结库存”“在途库存”必须是可解释的不同数量概念。
- 按操作手册口径：`可用库存 = 实际库存 - 锁定库存 - 冻结库存`；`实际库存 = 可用库存 + 锁定库存 + 冻结库存`；在途库存不计入实际库存总量。
- 库位库存与库存总量是不同聚合层级，不能用页面展示结果反推数据库表结构。
- 余额是当前状态，流水是已经发生的事实；库存修正应通过交易或调整记录完成，不直接覆盖余额。
- 批次、效期、序列号、库存属性、容器和库位是否全部进入库存粒度，要结合商品和仓库启用规则确定。

## 4. 字段定义与设计说明

### 4.1 库存余额 `inventory_balance`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `inventory_balance_id` | 库存余额标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `warehouse_id` | 仓库 | 关联 ID | BIGINT/UUID | 必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 多货主必填 |
| `location_id` | 库位 | 关联 ID | BIGINT/UUID | 库位库存必填 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 必填 |
| `inventory_attr` | 库存属性 | 正品/次品等 | ENUM | 默认正品，待确认 |
| `lot_no` | 生产批次 | 批次号 | VARCHAR | 按商品规则必填 |
| `production_date` | 生产日期 | 日期 | DATE | 按商品规则必填 |
| `expiry_date` | 过期日期 | 日期 | DATE | 按商品规则必填 |
| `serial_no` | 序列号 | 唯一序列号 | VARCHAR | 序列号商品按件记录 |
| `container_id` | 容器/货箱 | 关联 ID | BIGINT/UUID | 容器库存时必填 |
| `actual_qty` | 实际库存 | 数量＋基本单位 | DECIMAL | 默认 0 |
| `available_qty` | 可用库存 | 数量＋基本单位 | DECIMAL | 默认 0 |
| `locked_qty` | 锁定库存 | 数量＋基本单位 | DECIMAL | 默认 0 |
| `frozen_qty` | 冻结库存 | 数量＋基本单位 | DECIMAL | 默认 0 |
| `last_transaction_at` | 最近变更时间 | 日期时间 | DATETIME | 流水生效时更新 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `warehouse_id` / `owner_id` / `location_id` | 入库、出库、移库或调整生效时确定 | 仓库、货主、库位必须能回溯业务归属；库位库存与总量视图不能混为一表 | 支持多仓、多货主和区域统计 | 精确回答库存在哪里、属于谁 | 参考事实＋建议设计 |
| `product_id` / `inventory_attr` | 交易匹配商品和库存属性 | 次品不能只放在备注中；商品身份与库存属性要共同参与查询 | 支持正次品、质量隔离和货主库存 | 防止错误分配和错发 | 参考事实＋建议设计 |
| `lot_no` / `production_date` / `expiry_date` | 收货、移库或出库属性确认时写入 | 是否作为库存粒度、批次标准模式下的展示规则需保持一致 | 支持先进先出、效期预警和召回 | 实现批次级追溯 | 参考事实＋待确认 |
| `serial_no` | 序列号商品收货或出库时写入 | 序列号数量必须与库存数量一致，同一序列号不能重复占用 | 支持维修、售后和设备生命周期 | 定位单件商品的去向 | 参考事实＋建议设计 |
| `actual_qty` / `available_qty` / `locked_qty` / `frozen_qty` | 库存事务生效时更新 | 必须遵守数量公式，锁定和冻结的释放要有来源 | 支持 ATP、可接单库存和异常看板 | 让分配与现场账面一致 | 参考事实＋建议设计 |
| `last_transaction_at` | 每次库存生效时更新 | 不能把查询时间当成库存变更时间 | 支持库龄、变更监控和审计 | 定位最近库存变化 | 参考事实＋建议设计 |

### 4.2 库存流水 `inventory_transaction`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `transaction_id` | 库存流水标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `transaction_no` | 事务号 | 唯一编号 | VARCHAR | 必填 |
| `transaction_type` | 事务类型 | 入库/出库/移库/冻结/调整等 | ENUM | 必填 |
| `source_doc_no` | 来源单号 | 业务单号 | VARCHAR | 有来源时必填 |
| `source_line_no` | 来源明细行号 | 行号 | VARCHAR | 有明细时必填 |
| `task_no` | 来源任务号 | 任务号 | VARCHAR | 作业生效时可选 |
| `before_qty` | 变更前数量 | 数量 | DECIMAL | 必填 |
| `change_qty` | 变更数量 | 可正可负 | DECIMAL | 必填 |
| `after_qty` | 变更后数量 | 数量 | DECIMAL | 必填 |
| `operator_id` | 操作人/系统 | 用户或服务 ID | BIGINT/UUID/VARCHAR | 必填 |
| `effective_at` | 生效时间 | 日期时间 | DATETIME | 必填 |
| `reason_code` | 原因编码 | 异常/调整原因 | VARCHAR/ENUM | 调整场景必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `transaction_type` | 业务生效节点生成 | 事务方向和库存数量类型要清楚，不能用“修改库存”统称 | 支持经营分析和审计 | 解释库存为什么变化 | 建议设计 |
| `source_doc_no` / `source_line_no` / `task_no` | 单据或任务生效时写入 | 至少能回到来源单据、明细和执行任务 | 支持异常追溯和接口回写 | 让库存变化可查可证 | 归纳判断＋建议设计 |
| `before_qty` / `change_qty` / `after_qty` | 事务提交时计算并固化 | 不能只存当前余额，否则无法还原历史 | 支持重算、对账和冲销 | 发现重复或漏记账 | 建议设计 |
| `operator_id` / `effective_at` | 生效时写入 | 系统任务、人工操作和接口服务要能区分 | 支持责任和作业效率分析 | 明确谁在何时改变了库存 | 建议设计 |

### 4.3 库存预警与差异 `inventory_alert` / `inventory_difference`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `alert_scope_id` | 预警范围 | 商品/库区/区域关联 | BIGINT/UUID | 必填 |
| `lower_limit` | 预警下限 | 数量 | DECIMAL | 必填 |
| `upper_limit` | 预警上限 | 数量 | DECIMAL | 必填 |
| `dynamic_flag` | 是否动态计算 | `Y/N` | BOOLEAN | 默认 `N` |
| `replenishment_cycle` | 补货周期 | 天数 | INT | 动态预警时必填 |
| `safety_factor` | 安全倍数 | 小数 | DECIMAL | 动态预警时必填 |
| `difference_qty` | 库存差异量 | 数量，可正可负 | DECIMAL | 系统计算 |
| `difference_reason` | 差异原因 | 原因编码/文本 | VARCHAR/ENUM | 有差异时必填 |
| `adjustment_status` | 调整状态 | 待处理/已调整等 | ENUM | 默认待处理 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `lower_limit` / `upper_limit` | 手工设置、模板导入或动态计算 | 上下限适用范围必须明确；动态规则不能与手工值无提示覆盖 | 支持自动补货和库区健康监控 | 解决拣选区缺货 | 参考事实＋建议设计 |
| `dynamic_flag` / `replenishment_cycle` / `safety_factor` | 动态预警配置时写入 | 手册出现按 7 个补货周期计算和每日跑批，周期、公式和重算时间需保留版本 | 支持需求预测和安全库存 | 让预警随销量变化 | 参考事实＋待确认 |
| `difference_qty` | 差异页面或调整前计算 | 手册明确公式为“库位库存总量＋作业中数量－库存总量” | 支持自动生成调整候选 | 定位账面与明细不一致 | 参考事实＋建议设计 |
| `difference_reason` / `adjustment_status` | 差异识别和调整完成时更新 | 调整必须留下原因和通知结果，不能直接改总量 | 支持 ERP 对账和异常分析 | 形成库存差异闭环 | 参考事实＋建议设计 |

## 5. 功能与首版取舍

### 5.1 库存数量口径

| 数量 | 定义 | 是否计入实际库存 | 主要影响 |
| :--- | :--- | :---: | :--- |
| 实际库存 | 仓库实际拥有的账面数量 | 是 | 库存总量和库位余额 |
| 可用库存 | 实际库存扣除锁定和冻结后的数量 | 是 | 订单分配和可接单判断 |
| 锁定库存 | 已被订单或作业占用、不可再次分配的数量 | 是 | 拦截重复分配 |
| 冻结库存 | 因质量、异常或人工处理而不可正常使用的数量 | 是 | 隔离和解冻 |
| 在途库存 | 已下单或已产生入库意图、尚未入库的数量 | 否 | 采购和补货参考 |

### 5.2 功能优先级

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 库存总量和库位库存 | 库存维度、五类数量 | 必须统一数量口径和查询层级 |
| P0 | 库存流水和来源追溯 | 事务号、来源单、前后数量 | 没有流水就无法解释差异 |
| P0 | 批次、序列号和正次品查询 | 库存身份字段 | 按商品和仓库规则启用 |
| P1 | 历史库存、库龄和预警 | 快照、上下限、变更时间 | 支撑运营和补货分析 |
| P1 | 库存差异和调整候选 | 差异量、原因、状态 | 先保留差异事实，再进入 09 章调整 |
| 后续 | 预测库存、智能补货和库存健康评分 | 预测、模型和评分字段 | 依赖稳定历史数据，不作为核心余额字段 |

## 6. 跨模块依赖、拓展与待确认

- 入库生效增加实际库存；出库作业先影响锁定/可用，再在出库生效时减少实际库存；移库改变库位维度但不应改变仓库总量。
- 可拓展到 ATP、库龄、保质期预警、智能补货、3PL 货主库存和 ERP 对账。
- 作业中数量是否独立存储、在途来源是否统一、批次标准模式下的库存粒度、冻结库存是否允许被调整，均待确认。
