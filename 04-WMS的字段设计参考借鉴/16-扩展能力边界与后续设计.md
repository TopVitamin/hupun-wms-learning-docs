# 16 扩展能力边界与后续设计

> 本文件整理基于操作手册可以观察到、但不宜直接作为通用 WMS 核心字段的扩展能力。所有内容都要经过目标业务确认后再落地。

## 1. 扩展能力判断原则

扩展字段进入正式模型前，至少回答四个问题：

1. 它解决哪个具体业务问题？
2. 它依赖哪些核心字段和业务对象？
3. 它是通用能力、条件能力还是平台/行业专属能力？
4. 如果不启用，核心入库、库存和出库链路是否仍能运行？

## 2. 3PL 多货主与费用扩展

| 扩展内容 | 解决的问题 | 依赖字段/对象 | 采用边界 |
| :--- | :--- | :--- | :--- |
| 货主仓库授权 | 多货主共享仓库但数据需要隔离 | `owner_id`、`warehouse_id`、`data_scope` | 通用 3PL 条件能力 |
| 货主商品范围 | 不同货主商品编码、条码或规则不同 | 商品、货主、条码 | 条件采用 |
| 存储计费快照 | 按日库存、库位或体积计费 | 库存快照、货主、库位、计费规则 | 3PL 后续能力 |
| 作业计费 | 按收货、拣货、包装或出库量计费 | 作业任务、货主、数量、指标 | 3PL 后续能力 |
| 货权转移 | 货物实际位置不变但货主发生变化 | 库存、前后货主、审批、流水 | 高风险条件能力 |

## 3. 行业追溯与质量扩展

| 扩展内容 | 解决的问题 | 依赖字段/对象 | 采用边界 |
| :--- | :--- | :--- | :--- |
| 批次扩展属性 | 普通批次号不足以满足行业追溯 | 批次、生产日期、效期、属性明细 | 食品/医药/化妆品等条件能力 |
| UDI/追溯码 | 监管要求的单件或包装追踪 | 条码、序列号、批次、上传记录 | 行业插件 |
| 效期禁收/禁售 | 过期或临期商品不能收发 | `expiry_date`、商品规则、订单 | 通用能力＋行业规则 |
| 质检隔离 | 不合格商品不能进入正常可用库存 | 质检结果、库存属性、隔离库位 | 条件能力 |
| 复检/放行 | 质量状态可以经过再次判定 | 质检记录、审批、库存流水 | 待业务确认 |

## 4. 自动化与设备扩展

| 扩展内容 | 解决的问题 | 依赖字段/对象 | 采用边界 |
| :--- | :--- | :--- | :--- |
| WCS 设备范围 | 明确设备覆盖哪些库位 | 设备、库位范围、任务 | 自动化仓库条件能力 |
| 设备任务回传 | 现场设备异步反馈结果 | 任务、请求标识、回传状态 | 条件能力 |
| 设备失败转人工 | 设备异常时继续作业 | 任务状态、异常、人工接管 | 必须有明确副作用校验 |
| 自动上架/拣货 | 减少人工搬运和路径决策 | 库位、容器、任务、设备协议 | 后续能力 |
| 视频/操作关联 | 发生差异时回看现场 | 操作人、时间、工位、摄像头 | 运维或审计扩展 |

## 5. 平台和履约模式扩展

| 扩展内容 | 解决的问题 | 依赖字段/对象 | 采用边界 |
| :--- | :--- | :--- | :--- |
| 平台订单扩展属性 | 不同平台的订单识别和发货要求不同 | 来源平台、店铺、扩展属性、订单类型 | 适配层，不污染核心订单字段 |
| 即时零售 | 订单时效短、配送方式特殊 | 订单类型、时效、承运商、地址 | 履约模式扩展 |
| JIT/JITX | 平台档期和专配规则 | 平台单号、发运规则、承运商 | 平台专属能力 |
| 多包裹/子母件 | 一个订单对应多个包裹或运单 | 包裹、运单、明细分配 | 通用能力，但规则待确认 |
| 电子面单 | 获取并打印平台或承运商面单 | 店铺授权、承运商、运单、打印任务 | 平台/承运商适配能力 |

## 6. 数据分析与智能扩展

| 扩展内容 | 解决的问题 | 依赖字段/对象 | 采用边界 |
| :--- | :--- | :--- | :--- |
| 动态补货 | 固定上下限不能适应销量波动 | 库区库存、拣货历史、补货周期、安全倍数 | P1/P2 能力 |
| 路径优化 | 拣货和移库行走距离过长 | 库位优先级、坐标、任务轨迹 | 依赖现场数据 |
| 库存健康评分 | 识别呆滞、临期和差异风险 | 库存快照、流水、效期、订单 | 分析扩展 |
| 作业 SLA | 发现收货、拣货、发运超时 | 任务时间、状态、异常 | 运营扩展 |
| 智能异常识别 | 自动发现错拣、重复回传或异常库存 | 流水、日志、接口消息 | 后续能力，不替代基础流水 |

## 7. 不建议直接加入核心字段的内容

- 特定平台的临时扩展字段；
- 特定设备厂商的协议参数；
- 医药或其他行业专用属性；
- 只服务一个客户的打印字段；
- 只为某个报表临时计算的冗余字段；
- 尚未明确业务语义的“预留字段 1/2/3”。

这些内容可以放在扩展属性、适配层、配置表或独立插件中，但不能在核心商品、库存、入库和出库表中无边界堆积。

## 8. 后续落地顺序

1. 先完成通用主链：主数据、空间、入库、收货上架、出库、拣货发运、库存流水。
2. 再补 3PL、多货主、批次效期、序列号和盘点差异等高价值能力。
3. 然后接入接口、电子面单、设备和审批等运行支撑。
4. 最后建设动态补货、路径优化、预测和智能监控。
