# 11 查询、报表与作业监控字段设计

> 参考范围：`01-按章节拆分的md文件/08-库存管理.md`、`01-按章节拆分的md文件/11-客服与财务.md`、`01-按章节拆分的md文件/12-报表与运维辅助.md`、`03-WMS产品设计精华知识借鉴/11-查询报表与作业监控设计.md`
> 字段编码、长度和数据库属性均为建议设计；本章部分对象属于查询模型或统计结果，不代表一定需要单独落库。

## 1. 本章范围

### 1.1 包含哪些模块

库存查询、历史库存、库存预警、出入库报表、波次和拣货报表、入库上架报表、库龄、绩效、物流跟踪、耗材和运营看板。

### 1.2 包含哪些功能

按仓库、货主、商品、库位、批次、序列号、时间和状态查询；汇总、明细追溯、导出、看板展示、超时监控和异常定位。

### 1.3 业务场景与要解决的问题

报表和监控解决管理者无法及时知道“现在有什么、正在处理什么、哪里异常、谁完成了什么”的问题。操作手册覆盖库存总量、库位库存、作业看板、出入库报表、绩效、库龄、物流跟踪和耗材等内容。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 查询条件/视图 | 组织筛选维度和返回列 | 读取业务对象 | P0 |
| 报表结果 | 按固定口径汇总业务数据 | 来源单据/任务/库存 | P0 |
| 历史快照 | 保存指定时点的库存或指标 | 按日期和范围生成 | P1 |
| 导出任务 | 承载异步导出和下载结果 | 查询条件 1:N 任务 | P1 |
| 监控事件 | 保存超时、失败和异常指标 | 关联业务对象 | P0 |
| 指标定义 | 固化指标公式和数据口径 | 被看板/报表引用 | P1 |

## 3. 字段设计原则

- 查询展示字段不一定等同于底层存储字段，应标明来源对象和统计口径。
- 汇总数字必须能回到明细、单据、任务或库存流水，不能只保存不可解释的结果。
- “当前值”和“历史快照”分开；快照必须有统计时点、范围和生成状态。
- 指标名称、公式、单位和时间范围要一起定义，避免不同页面对同一指标产生不同解释。
- 导出是异步任务时，需要记录查询条件和结果状态，不把导出按钮视为同步下载必然成功。

## 4. 字段定义与设计说明

### 4.1 查询和报表结果 `report_query` / `report_result`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `query_id` | 查询标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `report_code` | 报表编码 | 编码 | VARCHAR | 必填 |
| `warehouse_id` | 仓库 | 关联 ID | BIGINT/UUID | 按报表必填 |
| `owner_id` | 货主 | 关联 ID | BIGINT/UUID | 货主报表必填 |
| `product_id` | 商品/SKU | 关联 ID | BIGINT/UUID | 商品报表可选 |
| `location_id` | 库位 | 关联 ID | BIGINT/UUID | 库位报表可选 |
| `date_from` | 开始时间/日期 | 日期时间 | DATE/DATETIME | 按报表必填 |
| `date_to` | 结束时间/日期 | 日期时间 | DATE/DATETIME | 按报表必填 |
| `status_filter` | 状态筛选 | 枚举集合 | JSON/ARRAY | 可选 |
| `result_scope` | 统计范围 | 当前/历史/快照 | ENUM | 必填 |
| `generated_at` | 结果生成时间 | 日期时间 | DATETIME | 系统生成 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `report_code` | 进入报表时确定 | 报表编码对应固定口径，不能只靠页面标题识别 | 支持报表版本和权限控制 | 防止同名指标口径不一致 | 建议设计 |
| `warehouse_id` / `owner_id` / `location_id` | 查询提交时写入 | 查询范围要与账号数据权限叠加，不可只按前端传值 | 支持多仓、多货主和库区分析 | 防止越权查询或跨仓误汇总 | 归纳判断＋建议设计 |
| `date_from` / `date_to` / `result_scope` | 查询或快照生成时写入 | 当前数据和历史快照不能混用，日期边界和时区需统一 | 支持日库存、库龄和周期分析 | 解释报表为何不同 | 参考事实＋待确认 |
| `generated_at` | 结果完成时写入 | 结果生成时间不等于业务发生时间 | 支持数据新鲜度监控 | 让用户知道报表是否滞后 | 建议设计 |

### 4.2 快照、导出与指标 `snapshot` / `export_task` / `metric_definition`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `snapshot_date` | 快照日期 | 日期 | DATE | 必填 |
| `snapshot_scope` | 快照范围 | 仓库/货主/商品等 | JSON/关联表 | 必填 |
| `metric_code` | 指标编码 | 编码 | VARCHAR | 必填 |
| `metric_formula` | 指标公式 | 文本/结构化公式 | TEXT/JSON | 必填 |
| `unit_code` | 指标单位 | 件、单、分钟等 | VARCHAR | 必填 |
| `export_task_id` | 导出任务标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `query_condition_json` | 导出查询条件 | 完整查询条件 | JSON | 必填 |
| `export_status` | 导出状态 | 排队/处理中/成功/失败 | ENUM | 默认排队 |
| `file_ref` | 文件引用 | 路径或对象存储键 | VARCHAR | 成功后写入 |
| `error_message` | 失败原因 | 文本 | TEXT | 失败时写入 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `snapshot_date` / `snapshot_scope` | 日终或指定时间生成 | 必须知道快照代表哪个时点和范围 | 支持存储费用、库龄和趋势 | 还原历史库存和业务状态 | 参考事实＋建议设计 |
| `metric_formula` / `unit_code` | 指标定义时维护 | 公式、分母、单位和时间范围要一起固化 | 支持多货主计费和绩效 | 避免“件数/单数/行数”混用 | 建议设计 |
| `query_condition_json` | 创建导出任务时保存 | 导出结果必须能复现当时查询条件 | 支持大数据量异步导出 | 解释下载文件的范围 | 建议设计 |
| `export_status` / `error_message` | 导出任务执行时更新 | 失败不能表现为空文件或无响应 | 支持重试和运营监控 | 提高导出可用性 | 建议设计 |

### 4.3 监控事件 `monitor_event`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `event_id` | 监控事件标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `event_type` | 事件类型 | 超时/失败/差异/库存预警等 | ENUM | 必填 |
| `source_type` | 来源对象类型 | 单据/任务/库存/接口 | ENUM | 必填 |
| `source_id` | 来源对象标识 | 关联 ID | BIGINT/UUID | 必填 |
| `severity` | 严重程度 | 提示/一般/高风险 | ENUM | 必填 |
| `event_status` | 处理状态 | 未处理/处理中/已关闭 | ENUM | 默认未处理 |
| `detected_at` | 发现时间 | 日期时间 | DATETIME | 系统生成 |
| `handled_by` | 处理人 | 用户 ID | BIGINT/UUID | 关闭时写入 |
| `handled_at` | 处理时间 | 日期时间 | DATETIME | 关闭时写入 |
| `resolution` | 处理结果 | 文本/原因编码 | VARCHAR/TEXT | 关闭时必填 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `event_type` / `source_type` / `source_id` | 系统检测异常时生成 | 必须能回到原单据、任务、库存或接口 | 支持异常中心统一处理 | 避免报表只显示红色数字而无法定位 | 建议设计 |
| `severity` / `event_status` | 规则判断和人工处理时更新 | 严重程度与处理状态是两个维度 | 支持升级、SLA 和责任分派 | 让异常有优先级和闭环 | 建议设计 |
| `resolution` | 异常关闭时写入 | 处理结果不能只改状态不留说明 | 支持问题分类和复盘 | 形成异常知识库 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 库存、单据、任务基础查询 | 范围、时间、状态、来源 | 先保证可定位业务事实 |
| P0 | 明细追溯和异常监控 | 来源对象、事件、处理状态 | 让指标可以回到业务对象 |
| P1 | 历史快照、库龄和绩效 | 快照日期、公式、单位 | 支撑经营分析和计费 |
| P1 | 异步导出 | 查询条件、状态、文件引用 | 应对大数据量导出 |
| 后续 | 预测分析、智能告警和实时数据平台 | 模型、规则、流式指标 | 依赖基础数据质量，不先定义为核心交易字段 |

## 6. 跨模块依赖、拓展与待确认

- 读取单据、任务、库存流水、物流、费用和操作日志；不直接修改交易数据或库存。
- 可拓展到 3PL 货主账单、库存健康、作业 SLA、物流超时、视频追溯和耗材成本。
- 报表快照时点、指标公式版本、历史数据是否允许重算、导出文件保留期限，均待确认。
