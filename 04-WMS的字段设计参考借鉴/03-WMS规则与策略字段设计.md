# 03 WMS 规则与策略字段设计

> 参考范围：`01-按章节拆分的md文件/03-仓内策略.md`、`01-按章节拆分的md文件/02-商品中心与库存属性.md`、`01-按章节拆分的md文件/05-出库_B2C.md`、`03-WMS产品设计精华知识借鉴/03-WMS规则与策略设计.md`
> 字段编码、长度和数据库属性均为建议设计，除非另有原始数据字典依据。

## 1. 本章范围

### 1.1 包含哪些模块

波次策略、订单分组、库存分配、库位分配、上架策略、补货策略、盘点策略、区域匹配、绩效和耗材匹配。

### 1.2 包含哪些功能

策略新增、复制、启用、停用、删除、条件配置、优先级配置、适用范围配置、自动执行和命中结果查询。

### 1.3 业务场景与要解决的问题

策略负责回答“订单如何分组、库存从哪里分配、货物放到哪里、什么时候生成补货或盘点任务”。操作手册中出现预配波次、普通波次、自由波次、一筐同品波次，并按货主、店铺、商品、品牌、区域、承运商、数量等条件匹配。

## 2. 业务对象与逻辑表

| 逻辑对象 | 主要职责 | 关系 | 采用建议 |
| :--- | :--- | :--- | :--- |
| 策略主表 | 保存策略身份、类型和生效范围 | 策略 1:N 条件/动作 | P0 |
| 策略条件 | 保存匹配字段、运算符和值 | 被策略引用 | P0 |
| 策略动作 | 保存命中后的分组、分配或任务动作 | 生成波次/任务 | P0 |
| 策略版本 | 固化变更前后的策略定义 | 被匹配记录引用 | P1 |
| 匹配记录 | 保存命中、未命中和失败原因 | 关联来源业务对象 | P0 |

## 3. 字段设计原则

- 策略条件和策略动作分开，避免把“匹配条件”与“执行结果”混成一个动态字段。
- 适用范围、优先级和生效时间必须能解释为什么某条策略先被使用。
- 策略本身不直接改库存；库存锁定、任务生成和库存流水由下游模块负责。
- 策略变更应采用版本或快照，历史任务保留生成时的规则依据。
- 未命中不能只返回“无结果”，要保存未命中原因，方便业务人员排查。

## 4. 字段定义与设计说明

### 4.1 策略主表 `strategy`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `strategy_id` | 策略标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `strategy_code` | 策略编码 | 编码 | VARCHAR | 必填 |
| `strategy_name` | 策略名称 | 文本 | VARCHAR | 必填 |
| `strategy_type` | 策略类型 | 波次/分配/上架/补货/盘点等 | ENUM | 必填 |
| `priority` | 策略优先级 | 正整数 | INT | 必填 |
| `warehouse_id` | 适用仓库 | 关联 ID | BIGINT/UUID | 可选，范围规则待确认 |
| `owner_id` | 适用货主 | 关联 ID | BIGINT/UUID | 可选 |
| `effective_from` | 生效时间 | 日期时间 | DATETIME | 可选 |
| `effective_to` | 失效时间 | 日期时间 | DATETIME | 可选 |
| `auto_execute` | 是否自动执行 | `Y/N` | BOOLEAN | 默认 `N` |
| `status` | 策略状态 | 草稿/启用/停用 | ENUM | 默认草稿或启用，待确认 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `strategy_type` | 新增策略时选择 | 不同类型允许的条件和动作不同 | 支持新增行业作业策略 | 让订单或库存进入正确作业链 | 参考事实＋建议设计 |
| `priority` | 策略维护时配置 | 相同对象命中多条策略时必须有稳定排序 | 支持货主级、仓库级覆盖 | 避免规则冲突造成结果不确定 | 参考事实＋建议设计 |
| `warehouse_id` / `owner_id` | 配置适用范围时写入 | 范围为空是否代表全局需要明确，不能隐式扩大 | 支持多仓、多货主策略隔离 | 防止策略跨仓误用 | 归纳判断＋待确认 |
| `effective_from` / `effective_to` / `status` | 发布或停用时更新 | 已生成任务不应因策略停用而被回溯修改 | 支持灰度发布和历史审计 | 降低规则变更风险 | 建议设计 |

### 4.2 条件、动作与版本 `strategy_condition` / `strategy_action` / `strategy_version`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `condition_field` | 条件字段 | 字段编码 | VARCHAR | 必填 |
| `operator` | 运算符 | 等于、包含、范围等 | ENUM | 必填 |
| `condition_value` | 条件值 | 文本/数组 | VARCHAR/JSON | 必填 |
| `action_type` | 动作类型 | 分组、分配、生成任务等 | ENUM | 必填 |
| `action_value` | 动作参数 | 文本/结构化参数 | JSON | 按动作必填 |
| `version_no` | 策略版本号 | 正整数 | INT | 系统生成 |
| `snapshot_json` | 策略快照 | 完整规则定义 | JSON | 版本生效时生成 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `condition_field` / `condition_value` | 策略编辑保存 | 字段类型、值域和运算符必须匹配 | 支持配置化波次和库位规则 | 避免规则配置成功但运行失败 | 建议设计 |
| `action_type` / `action_value` | 策略编辑保存 | 动作必须能被下游执行服务消费 | 支持新任务类型和自动化设备 | 将配置转成可执行结果 | 建议设计 |
| `snapshot_json` | 发布或命中时固化 | 不应只引用当前策略，否则历史任务无法解释 | 支持试算、审计和问题复盘 | 保留当时真实使用的规则 | 建议设计 |

### 4.3 匹配记录 `strategy_match_log`

| 字段编码（建议） | 字段名称 | 字段格式/长度 | 数据类型/数据库属性 | 必填/默认值 |
| :--- | :--- | :--- | :--- | :--- |
| `match_log_id` | 匹配记录标识 | 统一 ID | BIGINT/UUID | 系统生成 |
| `source_type` | 来源对象类型 | 订单/库存/盘点等 | ENUM | 必填 |
| `source_id` | 来源对象标识 | 关联 ID | BIGINT/UUID | 必填 |
| `strategy_version_id` | 使用策略版本 | 关联 ID | BIGINT/UUID | 必填 |
| `match_result` | 匹配结果 | 命中/未命中/失败 | ENUM | 必填 |
| `failure_reason` | 未命中/失败原因 | 原因编码/文本 | VARCHAR | 异常时必填 |
| `generated_task_id` | 生成任务 | 关联 ID | BIGINT/UUID | 生成任务时写入 |
| `matched_at` | 匹配时间 | 日期时间 | DATETIME | 系统生成 |

| 字段编码 | 来源/生成时机 | 设计关注点 | 拓展用途 | 业务场景/解决问题 | 事实级别 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `source_type` / `source_id` | 订单或库存事件触发 | 必须能定位本次匹配的业务对象 | 支持批量试算和异常复盘 | 解释某个对象为什么被分组 | 建议设计 |
| `strategy_version_id` | 匹配时写入 | 不能只保留策略当前版本 | 支持历史任务追溯 | 还原当时的匹配依据 | 建议设计 |
| `match_result` / `failure_reason` | 匹配结束时写入 | 失败原因要可分类统计，不能只存自由文本 | 支持异常队列和自动重试 | 让自动规则可运营 | 建议设计 |

## 5. 功能与首版取舍

| 优先级 | 功能 | 主要字段 | 取舍判断 |
| :--- | :--- | :--- | :--- |
| P0 | 策略启停、范围、优先级 | 类型、范围、优先级、状态 | 必须能控制新业务是否使用 |
| P0 | 波次、分配、上架和补货基础规则 | 条件、动作 | 覆盖核心仓内作业 |
| P0 | 命中日志和失败原因 | 匹配结果、原因、版本 | 保证自动规则可解释 |
| P1 | 复制、版本、试算和冲突检测 | 版本、快照 | 降低规则变更风险 |
| 后续 | 预测补货、路径优化、复杂算法 | 模型参数、评分 | 依赖稳定历史数据，不作为首版前置条件 |

## 6. 跨模块依赖、拓展与待确认

- 读取商品、货主、店铺、库位、库存和订单字段；向波次、分配、补货、上架和盘点任务提供规则结果。
- 可拓展到动态补货、库位路径优化、自动化设备分配、耗材推荐和绩效策略。
- 条件组合方式、策略冲突优先级、范围为空的含义、策略版本生效时间和任务撤销规则，均待确认。
