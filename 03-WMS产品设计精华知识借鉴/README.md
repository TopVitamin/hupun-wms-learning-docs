# 03 WMS 产品设计精华知识借鉴

## 1. 目录说明

本目录以万里牛 WMS 操作手册为参考事实源，提炼可复用的 WMS 产品设计，再形成一套不依赖万里牛菜单结构的通用型 WMS 方案。

文档中的内容严格区分四种边界：

- **参考事实**：万里牛手册明确记载或展示的内容。
- **归纳判断**：从多个章节、多个操作环节整理出的设计规律。
- **建议设计**：面向通用型 WMS 提出的产品、数据和流程方案，不表示万里牛已有此设计。
- **待确认**：资料不足、存在多种合理方案或需要结合目标业务确认的内容。

## 3. 跨模块设计基线

1. 业务单据负责表达业务意图，执行任务负责表达现场工作，库存对象负责表达当前数量，库存流水负责表达已经发生的事实。
2. 单据状态、任务状态、库存影响和外部同步必须在同一个操作事务中定义，不能只根据页面按钮推导规则。
3. 参考事实中的平台专属、医药专属、3PL 专属和设备专属能力，默认作为扩展能力，不直接进入通用 WMS 核心闭环。
4. 所有库存变化都必须能追溯到来源单据、执行任务、操作人、操作时间和库存流水；资料未说明的字段和规则标记为待确认。
5. 通用首版优先覆盖 SKU、批次、效期、库位、收货、上架、分配、拣货、复核、出库、盘点和库存流水，复杂平台插件与自动化设备作为后续能力。

## 4. 设计与参考关系

本目录不是万里牛 WMS 的产品说明书，也不把万里牛的菜单、页面名称或特定平台规则直接当作通用 WMS 规范。每个模块都包含“参考范围”“借鉴判断”和“待确认问题”，用于追溯设计来源和识别适用边界。13、14 两个补充模块直接列出原始文件路径，用于示范如何把分散在 01 层的加工、费用、账单和对账内容独立建模。

## 5. 本轮扩充后的阅读方式

每个模块的内容按以下顺序阅读：

1. **场景说明**：先理解什么时候使用、为什么使用，以及 WMS 解决什么业务问题。
2. **业务/系统流程**：区分现场参与者的业务动作和系统内部的校验、生成、回写过程。
3. **实体与单据关系**：用中文 ER 图和数量关系表说明对象边界；1:N 表示可能拆分，不表示每次都必然拆分。
4. **状态与操作矩阵**：确认状态进入条件、操作前提、后续结果以及是否生成任务、流水或关联单据。
5. **表头/明细字段**：字段表同时说明来源、必填性、可修改时点、展示用途、校验和下游影响；字段类型/长度不是资料已确认的数据库设计。
6. **功能说明与首版取舍**：将功能放回具体场景，说明解决的问题、上下游影响及 P0/P1/后续边界。
7. **详细借鉴判断**：按通用性、业务价值、闭环完整性、实现成本和边界风险判断“直接借鉴、改造后借鉴、不照搬、需要补充或待确认”。

### 借鉴判断的统一标准

| 判断层 | 核心问题 | 不合格表现 |
|---|---|---|
| 事实层 | 手册是否明确写出或展示？ | 把按钮、页面标题或推测流程写成事实 |
| 业务层 | 是否解决真实的收发存、协同、追溯或管理问题？ | 只罗列功能，不说明使用场景 |
| 模型层 | 单据、任务、库存、流水和主数据是否边界清楚？ | 订单、任务和库存共用一个模糊状态 |
| 闭环层 | 正向、异常、取消和反向处理能否闭环？ | 只写成功路径，不写差异和释放 |
| 通用层 | 能否跨仓型、货主、行业和平台复用？ | 把平台、设备、3PL 或行业特性硬编码为核心 |
| 落地层 | 首版是否能以明确规则稳定实现？ | 为追求完整虚构算法、接口、字段或状态 |

## 6. 新手阅读路径

建议先读 [02 跨章节主链与学习导航](../02-按章节拆分的流程图/00-跨章节主链与学习导航.md)，再选择入库、出库或库存异常中的一个场景。完成 01 层事实核对和 02 层流程分支后，再读本目录对应模块，最后用 04 层字段表写出可验收的模型。

对于容易被忽略的非主链能力，建议单独阅读：仓内加工看 [13-仓内加工与作业结果设计](13-仓内加工与作业结果设计.md)，3PL 结算看 [14-3PL费用、货主协同与结算设计](14-3PL费用货主协同与结算设计.md)，现场体验和异常恢复看 [15-仓内作业体验与异常反馈设计](15-仓内作业体验与异常反馈设计.md)。它们分别练习“原料/费用事实 → 任务或明细 → 状态 → 结果 → 反向处理”和“当前对象 → 现场结果 → 异常反馈 → 恢复动作”的完整设计。
