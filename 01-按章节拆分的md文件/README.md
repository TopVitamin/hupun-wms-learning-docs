章节正文保留源文档中的操作步骤、业务规则、校验条件与图文引用；章节编号、目录和来源标记属于本次整理的结构信息，未新增业务规则或功能假设。

## 3. 组织与迁移原则

1. **事实第一**：所有章节正文与操作说明直接继承自 `00-源文件/`，不新增未经源文档记载的业务规则、字段或流程。
2. **多端融合**：在同一个业务主题下，将 PC 端控制台功能、PDA 移动终端操作、专题特性有机整合为一个完整章节。
3. **图文可溯**：内部保留每一个小节对应的原始源文件路径（`> 原始文件来源：...`），所有图片均自适应解析为相对路径引用，确保图文完整展现。

## 4. 源文件范围说明

`00-源文件/` 共包含 330 个 Markdown 文件：314 个业务正文文件已纳入本目录的 12 个章节，另外 16 个仅承担目录导航作用的 `index.md` 保留在源目录中，不重复展开。9 个包含实际业务正文的 `index.md` 已按业务域补入对应章节。

## 5. 保守整理说明

在不改变业务事实的前提下，本目录对正文做了有限的 Markdown 编辑整理：统一标题层级、列表符号、连续空行、标题样式和明显的中英文标点，并将部分说明文字与截图拆为独立段落。字段名、业务规则、操作步骤、数量和状态均不作改写；含义不明确的原文保留原样。

## 6. 新手阅读方法

01 层是“事实层”，不是完整 PRD。建议每次只选一个场景，按以下顺序阅读：

1. 先看章节中的原始来源标记，确认事实来自哪个文件；
2. 再提取参与对象、页面动作、前置条件、结果和异常；
3. 把不确定的库存生效时点、状态含义或接口结果标记为“待确认”；
4. 进入 [02 流程图](../02-按章节拆分的流程图/README.md) 看分支，进入 [03 产品设计](../03-WMS产品设计精华知识借鉴/README.md) 看抽象，最后进入 [04 字段设计](../04-WMS的字段设计参考借鉴/README.md) 落字段。

跨章节学习建议先看 [跨章节主链与学习导航](../02-按章节拆分的流程图/00-跨章节主链与学习导航.md)，否则容易把“订单状态”“任务状态”和“库存状态”混成一个状态。
