# 02 流程图与关键逻辑说明层

## 1. 目录说明

本目录基于 `00-源文件/` 的操作手册、专题功能介绍和 PDA 文档，将已在 `01-按章节拆分的md文件/` 中按章节整理的内容，进一步转化为 Mermaid 流程图、时序图、对象关系图，以及配套的文字说明和表格。

流程图不是唯一交付物。每章同时保留图表用途、原文依据、编号说明、关键逻辑、条件与结果表格，以及“事实边界 / 原文未说明”说明。

## 2. 输出结构

目录按 `01-按章节拆分的md文件/` 的 01—12 章对应组织，并增加一个跨章节总览文档：

```text
02-按章节拆分的流程图/
├── README.md
├── 00-跨章节主链与学习导航.md
├── 01-基础信息与系统设置.md
├── 02-商品中心与库存属性.md
├── 03-仓内策略.md
├── 04-入库操作.md

├── 08-库存管理.md

├── 11-客服与财务.md
└── 12-报表与运维辅助.md
```

每个章节最多输出 3 张 Mermaid 图；00 总览文档用于补足跨章节主链、库存异常回流和学习入口，不替代各章的事实边界。不适合形成明确流程的内容，以文字说明或表格呈现，不为凑数量强行画图。

本轮暂不输出 PNG、SVG 等静态图片。

## 3. 每章与每张图的固定结构

每章包含：

1. 本章图表目录；
2. 图表正文；
3. 关键逻辑说明；
4. 必要的条件、结果、角色或节点说明表；
5. 事实边界和原文未说明项。

每张图统一包含：

1. 图表标题与用途；
2. 原文依据：源 Markdown 文件、原文小节、对应的章节定位；
3. Mermaid 代码；
4. 简短的编号说明；
5. 事实边界 / 原文未说明。

## 4. 图表分层规则

- 粗略图：只呈现业务主链或对象主关系，控制在少量核心节点。
- 中等图：呈现源文档明确写出的关键步骤和判断分支。
- 细节图：只展开确实影响理解的判断逻辑、计算方向或系统处理结果。
- `flowchart` 用于流程、分支、层级和对象关系。
- `sequenceDiagram` 仅用于源文档明确写出角色交接或系统交互的场景。
- 一张图只解决一个层次的问题，不把所有字段、页面截图和配置项塞进同一张图。

## 5. 事实边界

- `00-源文件/` 是唯一事实源，`01-按章节拆分的md文件/` 只用于章节定位和阅读辅助。
- 节点名称优先使用操作文档中的原词，不自行补充业务术语。
- 每个节点、箭头、判断、状态和结果都必须能追溯到源文档。
- 不根据行业常识推导未写明的状态、字段、权限优先级、接口行为、算法或异常结果。
- 原文只写“支持某功能”但没有明确前后顺序时，不画成确定流程。
- 原文没有说明后续处理的地方，直接标注“原文未说明”或“待确认”，不擅自补全箭头。
- 对原文进行的文字调整仅限于图表解释和排版组织，不改写源文档中的业务规则、操作步骤、数量和状态。

## 7. 验证方式

完成每批输出后逐项验证：

- 章节文件名与 `01-按章节拆分的md文件/` 对应；
- 每章图表数量不超过 3 张；
- Mermaid 代码块成对闭合，图表类型正确；
- 每张图均有具体源 Markdown 文件和原文小节依据；
- 节点、箭头、判断和说明不存在无事实依据的扩展；
- 使用临时 Mermaid 渲染环境逐张检查语法和布局，临时依赖不写入项目正式目录；
- 抽查粗略图、中等图、细节图和时序图的分层是否清楚；
- 检查图表说明和表格是否真正解释关键逻辑，而不是重复抄录正文。
